## 2. 实现映射（v1.7.0 设计 → 代码）

### 2.1 RunnerInvocation（§2 Input Model）

`types.ts` 定义：

- `RunnerInvocation` = AgentRun 引用 + AgentRuntimeInstance 引用 + AgentExecutionContext 引用 + TaskInput + timeout_ms。
- `TaskInput`（goal / prompt_source / workspace / memory_ns / permissions / execution_id / instance_id / agent）——**全部取自既有引用字段，不新建任何值**；`prepareTaskInput()` 只做投影，维持「引用而非复制」。

### 2.2 RunnerResult（§3 Output Model）

- `RunnerResult` = status + output + artifacts + nextAction + meta。
- `RunnerArtifact`（name / path / size / modified / kind）只登记执行体落盘产物的描述；Runner 不写 result 目录。
- `nextAction`（continue / human_checkpoint / transition / complete / fail）由 `produceNextAction()` 生成：`checkpointRequested → human_checkpoint`；`!ok → fail`；其余 `complete`。

### 2.3 ToolInvocationPort（§4 Tool Boundary）

- 接口 `ToolInvocationPort.invoke(request): Promise<ToolInvocationResult>`。
- 本阶段**不接入真实工具**：调用方注入 mock port；测试的 mock 严格验证「allowed tool 转发、denied tool 拦截」。
- `invokeTool()` 承担 Runner 侧的校验 → 组装 → 转发：未声明工具 / source 不匹配 / `allowed=false` / 路径越出 allowed+进入 deny 域 → 抛 `RunnerValidationError`（不绕过、不转发）；通过后才调用 port。

### 2.4 Runner.execute()（§4 流程）

```
validate invocation → prepare context → executor(适配器) → normalize → nextAction
   └─ 所有异常 → mapError → 失败 RunnerResult（不外泄裸异常）
```

- 无超时：直接执行，异常折叠为失败结果。
- 有超时：`Promise.race` + 超时守卫，超时映射为 `timeout` kind。
- 取消：`AbortSignal` 在 executor 返回后仍 aborted → 映射 `cancel` kind。

### 2.5 Error Mapping（§5）

`mapError()` 分类表：

| 场景 | kind |
|---|---|
| `RunnerValidationError`（非法 invocation） | assertion_error |
| 工具重试耗尽后失败 | tool_error |
| 执行体抛异常 | agent_error |
| 超时守卫触发 | timeout |
| signal aborted / AbortError | cancel |
| 其它 | agent_error |

工具重试：`invokeTool` 内置 `max_retries=2` + 指数退避，仅 tool 失败可重试。

### 2.6 Checkpoint（§6）

- Runner 在 `checkpointRequested` 时只产出 `nextAction = "human_checkpoint"`（status = checkpoint_requested），**不自动 resolve / 不自动 continue**（设计 §6.3「Runner 只产不答」）。
