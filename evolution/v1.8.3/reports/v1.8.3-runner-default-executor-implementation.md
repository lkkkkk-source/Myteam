## 2. 实现映射（v1.8.2 设计 §3 责任矩阵 → 代码）

### 2.1 缺口的补齐

v1.8.2 设计 §0.1 指出：`Runner`（`RunnerDeps{toolPort, executor}` 注入式）已具备注入能力，
但**没有任何工厂把「默认执行体」装进去**——上层每次必须自己 `new` 执行器，存在旁路与
遗漏风险（S-1 单向链被打破）。

本阶段新增**唯一工厂** `createRunnerDeps()`，把「组装 `RunnerDeps`」这件事收敛到一处：

```ts
export function createRunnerDeps(options: CreateRunnerDepsOptions): RunnerDeps {
  const executor =
    options.executor ??
    createAgentExecutor(options.context, options.instance, options.toolPort, options.signal);

  return {
    toolPort: options.toolPort,
    executor,
    now: options.now,
    signal: options.signal,
  };
}
```

### 2.2 与 §3 责任矩阵的一致性

| 对象 | 设计责任 | 实现落点 | 一致 |
|---|---|---|---|
| `RunnerDeps` | RuntimeFactory 组装 | `createRunnerDeps()` | ✅ |
| `ToolInvocationPort` | 由工厂注入（不新建） | `options.toolPort` 透传，同一实例 | ✅ |
| `AgentExecutor` | 默认实现 / 可覆盖 | `options.executor ?? createAgentExecutor(...)` | ✅ |
| `now` / `signal` | 可选透传 | 缺省 `undefined`，显式传入则透传 | ✅ |

### 2.3 契约要点

- **默认执行器**：未显式传入 `executor` 时，工厂调用既有 `createAgentExecutor(context, instance, toolPort, signal)`
  生成 `AgentExecutorImpl`——**复用** v1.8.0 的执行体，不重复实现。
- **可覆盖**：显式传入 `executor` 时以调用方为准（向后兼容 v1.7.1 的 mock 注入测试路径）。
- **同实例无旁路**：返回的 `deps.toolPort` 与传入的 `options.toolPort` **严格同一引用**，
  执行器拿到的也是同一 `toolPort`，保证 `Runner → ToolAdapter → HostPort` 单向链（S-1）。
