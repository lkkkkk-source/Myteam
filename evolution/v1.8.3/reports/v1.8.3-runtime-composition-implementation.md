## 2. 实现映射（v1.8.2 设计 §2 契约 → 代码）

### 2.1 唯一装配点（I-1）

`createRuntime()` 是全仓库**唯一** `new ToolAdapter` / `createOpenCodeHostPort` 之处。
装配顺序（`create-runtime.ts`）：

1. **HostPort**：`createOpenCodeHostPort(host.client, directory)`（只读路由，目录优先 `host.directory`）。
2. **ToolPort**：有 `execContext` → `new ToolAdapter(execContext, {hostPort, now})`；
   否则惰性占位 `INERT_TOOL_PORT`（任何调用即抛 `CompositionError`）。
3. **EngineFacade**：`createEngineFacade(resolution)`——内部把 Store 搬运函数绑定为 `EngineDeps`。
4. **RunnerFacade**：`createRunnerFacade({toolPort, instance, execContext, executor, signal, now})`；
   缺 `instance`/`execContext` 时惰性化（`deps=undefined`，`execute` 抛错）。

### 2.2 与 §2 责任矩阵的一致性

| 对象 | 设计责任 | 实现落点 | 一致 |
|---|---|---|---|
| `HostPort` | 组装层创建（工厂） | `createOpenCodeHostPort` | ✅ |
| `ToolInvocationPort` | 组装层创建（构造器注入） | `new ToolAdapter(...)` / `INERT_TOOL_PORT` | ✅ |
| `EngineDeps` | 绑定 Store（9 函数） | `bindEngineDeps(res)` | ✅ |
| `RunnerDeps` | 组装层组装（`createRunnerDeps`） | `createRunnerFacade` | ✅ |
| `describe()` | 只读自检 | `RuntimeDescriptor`（无可变状态泄漏） | ✅ |

### 2.3 契约要点

- **S-1 无旁路**：`runner.deps.toolPort === ports.toolPort`（严格同引用，测试 §3 断言）。
- **I-2 只读**：默认工作目录 `instance.workspace ?? resolution.project_root`；组装层不写盘。
- **I-3 无副作用装配**：缺 `instance`/`execContext` 仍可无副作用返回句柄（惰性）。
- **I-5 无宿主写**：不写宿主全局配置目录 / `myteam_home`；不调用 `resolveWorkspace` /
  `ensureTeamRoot` / `activateAgent`（Entry 职责，测试 §10 静态断言）。

### 2.4 惰性占位的一致性修正

初版实现中 `create-runtime.ts` 与 `runner-facade.ts` 各自定义了一个 `INERT_TOOL_PORT`
对象，导致 `isToolPortInert()` 的**引用相等**判定在无 `execContext` 场景下失配
（describe 误报 `ToolAdapter`）。修正为**单一共享实例**：`runner-facade.ts` 导出
`INERT_TOOL_PORT`，`create-runtime.ts` 复用同一引用。

## 3. 测试设计（composition.test.ts，62 断言）

| # | 用例 | 断言要点 |
|---|---|---|
| 1 | 惰性装配（无 instance/execContext） | 返回句柄；`hostPort` 为 `OpenCodeHostPort`；`runner.deps===undefined`；`describe.toolPortKind=InertToolPort`；`readOnly=true`；`runStep` 抛 `CompositionError` |
| 2 | 完整装配（instance+execContext） | `toolPort instanceof ToolAdapter`；`instance`/`execContext` 绑定；`describe.hasInstance/hasExecContext=true`；`toolPortKind=ToolAdapter`；`workspace=instance.workspace` |
| 3 | 单一装配点 / 无旁路 | `runner.deps.toolPort === ports.toolPort`；默认 executor 为 `AgentExecutorImpl` |
| 4 | EngineFacade 绑定（T3） | `engine.deps` 有 9 个函数；暴露 `transition` / `resolveCheckpoint`；**`deps.save`/`deps.load`/`deps.listRunIds` 转发到 Store**（磁盘真相命中） |
| 4b | 组装幂等（T10） | 两次 `createRuntime` 返回不同句柄 / 不同 hostPort；`describe()` 等价 |
| 5 | `runStep` 端到端（completed） | `result.status=completed`；`output=goal`；`execution/run.status=completed`；**磁盘真相** `runtime/execution/<EX>/execution.yaml` 落盘 |
| 5b | `runStep` 端到端（checkpoint，T6） | `status=checkpoint_requested`；`nextAction=human_checkpoint`；`execution=paused`；**checkpoint 落盘**于 `checkpoints/`，`message` 携带 runner output |
| 5c | `runStep` 端到端（executor 失败） | `status=failed`；`meta.error=agent_error`；`execution=failed` |
| 6 | `describe()` 自检 | `resolution === res`；`hostPortKind`；`readOnly` |
| 7 | 显式 executor 覆盖 | mock 被调用；`output=mock-output`（向后兼容） |
| 8 | `runStep` 缺 instance | 抛 `CompositionError` |
| 9 | I-3 无副作用装配 | `createRuntime` 本身不改 `team_root`、不建 `runtime/` 目录 |
| 10 | 禁则（静态） | `create-runtime.ts` 源码不含 `.config`/`opencode.json`/`resolveWorkspace`/`ensureTeamRoot`/`activateAgent` |

### 3.1 对设计 T1–T10 的覆盖

| 设计用例 | 状态 | 覆盖点 |
|---|---|---|
| T1 返回句柄 / ports 齐全 | ✅ | §1、§2 |
| T2 `describe()` 报告来源 | ✅ | §1、§2、§6 |
| T3 `engineDeps.load/save` 转发 Store | ✅ | §4（新增） |
| T4 `runnerDeps.toolPort === ports.toolPort` | ✅ | §3 |
| T5 `runStep` → execution=completed | ✅ | §5 |
| T6 `runStep` → paused + checkpoint 落盘 | ✅ | §5b（新增） |
| T7 toolPort 拒绝 → Runner failed；HostPort 未调用 | ✅（runner 层覆盖） | `runner.test.ts`：工具边界单测；组装层用例 5c 覆盖 `failed` 推进链路 |
| T8 安全域越界 → assertion_error，无宿主写 | ✅（adapter 层覆盖） | `tool-adapter/adapter.test.ts`：`checkSecurityDomain: host config write rejected` |
| T9 全程无宿主写 | ✅ | §9（无副作用）+ §10（静态禁则） |
| T10 `createRuntime` 幂等 | ✅ | §4b（新增） |

> T7/T8 的触发点位于 **runner**（工具下行）与 **adapter**（安全域）层，不在组装层可达范围
> （默认执行体为占位 stub，不调用 `toolPort`）。故这两项复用其所属层的既有回归，
> 组装层只断言对应**推进链路**（5c）与**零宿主写**（§9/§10），避免重复造桩。

### 3.2 修正的测试缺陷

- 用例 5 原断言落盘路径为 `runtime/executions/`（复数），与 Store 实际布局
  `<team_root>/runtime/execution/<EX-xxx>/`（单数）不符，属**测试笔误**；
  已对齐 Store 契约（`execution-store.ts` 的 `executionDir()`）。
- 用例 5b 初版断言 `checkpoint.message === 执行体提供的 checkpointMessage`，与
  `runner-engine-adapter` 现有映射（`message = result.output`）不符，已按实际契约修正。

## 5. 发现（超出本阶段范围，记录待后续处理）

1. **执行体 checkpoint 文案丢失**：`AgentExecutorResult.checkpointMessage` /
   `checkpointOptions` 经 `runner-engine-adapter.mapRunnerResultToEngineAction`
   映射时**未被采纳**——checkpoint 的 `message` 恒取 `result.output`，
   `options` 恒为 `["continue","modify","reject"]`，`required_action` 写死。
   本阶段组装层不修改 runner 语义，仅记录；建议 v1.8.4（真实执行体接入）时
   一并把人类确认文案从执行体透传到 checkpoint。
2. **T7/T8 无组装层专属用例**：因默认执行体为不触工具的占位 stub，
   组装层无法在无真实宿主下复现"工具被拒 / 安全域越界"。当前以跨层回归覆盖；
   若后续要求组装层端到端覆盖，可在 v1.8.5（Trace 埋点）引入可注入的
   拒绝型 toolPort 后补齐。

## 6. 边界与后续

### 6.1 本阶段不做

- ❌ 真实模型推理执行体（替换 stub）——属 v1.8.4。
- ❌ Trace Event Bus 埋点——属 v1.8.5。
- ❌ OpenCode 插件 `index.ts` 生命周期接入（Entry 层调用 `createRuntime`）——属后续阶段。

### 6.2 验收断言（本阶段）

1. `createRuntime()` 为唯一装配点；`ports` 四项（hostPort/toolPort/engine/runner）齐全。
2. `Runner → ToolAdapter → HostPort` 单向链无旁路（`toolPort` 同引用）。
3. 惰性装配：无 `instance`/`execContext` 时可无副作用返回句柄，使用即抛 `CompositionError`。
4. `runStep` 端到端打通 `Runner → Engine → Store`：completed / paused+checkpoint / failed
   三条路径均落盘正确的磁盘真相。
5. 组装层零宿主写、零 Entry 越权（静态断言）；`createRuntime` 幂等。
