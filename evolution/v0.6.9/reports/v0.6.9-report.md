# Model Routing Feedback Loop — v0.6.9 Report

> 阶段：v0.6.9 · Model Routing Feedback Loop（模型路由反馈闭环 / Model Recommendation Intelligence）
> 目标：在 v0.6.8 **Model Recommendation** 之上，让系统「知道」**什么任务适合什么模型能力档位**——基于历史反馈沉淀『任务 ↔ 档位』适配知识；同时保持**人工审核、策略可追踪、不自动改变行为**。
> 升级前基线：Agent=30 MCP=5 Skill=26 Workflow=8（**不变**）
> 状态：完成（反馈闭环设计 + 一致性测试通过；未实现任何自动调整 / 自动切换）

## 1. 分层定位（v0.6.9 在链路中的位置）

在 v0.6.8 的 Model Recommendation 之上，为「推荐有效性」建立反馈回路：

```
Task → Router → Team → Agent → Model Recommendation → Execution
                                          ↑              │
                                          │   实际结果    ▼
                                   Feedback（记录 / 统计 / 沉淀知识）
                                            │
                                            ▼
                                 Improvement Proposal（人工审核）
                                       │            │
                                   approved     rejected
                                       │            │
                               更新 routing-policy   policy 不变
                               + change_log(可回滚)
```

- **升级点**：Model Recommendation（v0.6.8，只推荐）→ **Model Recommendation Intelligence**（v0.6.9，能从反馈中沉淀『任务↔档位』知识）。
- **不变点**：仍**不自动切换**模型 / Provider / 不自动改策略；所有策略变更走 proposal + 人工审核。

### Feedback 数据模型（核心判定）

`match_verdict`：`good-fit` / `over-provisioned`（档位过强）/ `under-provisioned`（档位不足）/ `mismatch`（档位不合理）。
`outcome`：`success` / `failure` / `pending-human-confirmation`（高风险，确认前不视为有效）。

## 3. Improvement Proposal 机制

**流程**：`feedback → metrics → analytics(findings) → proposal(draft) → engops-lead 人工审核 → approved(release+change_log) / rejected(关闭，policy 不变)`。

| 提案 | triggered_by | decided_by | 决策 | 结果 |
|---|---|---|---|---|
| P-069-01 | FH-069-003（research + large context **over-provisioned**） | engops-lead | **approved** | merge 进 routing-policy v2（MR-3 改按 context 分级），留 change_log，可回滚 |
| P-069-02 | FH-069-004（content **under-provisioned**） | engops-lead | **rejected** | routing-policy / model-registry **保持原样** |

**判例（Case5）**：单条 / 少量 under-provisioned 反馈**不足以**支撑全局档位上调（成本 / 风险考量）。P-069-02 被拒后，content 任务仍走默认档位（general），策略未变。

## 5. 硬性边界（强制）

- feedback / metrics / analytics **只记录、只统计、只沉淀**，不自动改策略。
- 策略变更**唯一**入口 = improvement proposal + engops-lead 人工批准。
- 不自动切换模型 / Provider / 不自动调用模型；仅维护推荐策略元数据。
- 高风险（human_confirm=true）反馈未经人工确认不视为有效。
