## 1. 状态转移 API（State Driver）

| 函数 | 语义 | 转移边 |
|---|---|---|
| `transition()` | load → validate → save | 任意合法边 |
| `pause()` | running → paused | 单边 |
| `resume()` | paused → running | 单边 |
| `complete()` | running → completed | 单边 |
| `fail()` | 任意非终态 → failed | 多入边 |

**实现细节（对照设计 §2.3）：**

- `transition()` 每次先 `deps.load()` 读磁盘真相，再查转移表，再 `deps.save()` 原子落盘（写 `.tmp` 后 rename，复用 Store 的 `writeAtomic`）。
- **非法转移 → 抛 `EngineTransitionError`，不写盘**（测试 2 验证磁盘状态保持 `received`）。
- **幂等（同态 no-op）**：`cur.status === to` → 直接返回当前态，不写盘。
- **终态吸收**：completed/failed 上调用任何"不同目标"转移 → 抛 `EngineTransitionError`；`fail()`/`complete()` 对终态调用 → 幂等返回。

转移表（Engine 唯一合法来源）：

```
received            → planning / failed
planning            → awaiting_confirmation / ready / failed
awaiting_confirmation → ready / planning / failed
ready               → running / paused / failed
running             → awaiting_confirmation / paused / completed / failed
paused              → ready / running / failed
completed / failed  → （吸收态，无出边）
```

## 2. AgentRun API（只写 Store）

| 函数 | 语义 | 状态转移 |
|---|---|---|
| `createRun()` | 递增 id（run-0001…）+ status=received | 无（execution 状态不受影响） |
| `startRun()` | received → running | 幂等 |
| `completeRun()` | running → completed（写 output + completed） | 幂等 |
| `failRun()` | running → failed（写 output + completed） | 幂等 |

**实现细节：**

- id 递增基于 `runs/` 目录已有文件名（`listRunIds` dep），纯数字 padStart(4)。
- run 状态与 execution 状态**相互独立**：`createRun` 不改变 execution.status（测试 5 验证）。
- 非法 run 转移（如对 received 的 run 调 `completeRun`）→ 抛 `EngineRunStateError`。

## 3. Checkpoint：resolveCheckpoint（continue / modify / reject）

| 响应 | 转移 | 副作用 |
|---|---|---|
| `continue` | awaiting_confirmation → ready → running（两跳，两次原子写） | cp 标记 resolution + resolved_at + acknowledged |
| `modify` | awaiting_confirmation → planning | cp 标记 resolution=modify + resolved（携带修改意图） |
| `reject` | awaiting_confirmation → failed | cp 标记 resolution=reject |

**实现细节：**

- 一次响应 = 两个原子写：先落 checkpoint，后驱动状态转移（先 cp 后 exec）。
- **单次响应**：已 `resolved_at` 的 cp 再次 resolve → 抛 `EngineCheckpointResolvedError`（测试 4 验证 double resolve rejected）。
- **continue 走两跳**：`awaiting_confirmation → ready → running`。v1.6.6 设计 §2.2 状态表规定 `awaiting_confirmation` 的出边只有 ready/planning/failed（无 running 直达），continue 须经 ready 中转。

## 4. 持久化与崩溃恢复

- **真相全在磁盘**：每次操作先 load；每次转移是单原子写。
- `recover()`：重新 load 当前真相并返回；终态返回终态（幂等），缺失抛 `EngineNotFoundError`。
- **崩溃恢复 = 重读 + 重放剩余合法转移，无需日志回放**（测试 6 用全新 deps 重放 running→paused→running）。

## 5. 架构（deps 注入）

`EngineDeps` 接口把全部磁盘 IO 委托给 Store（load/save/saveRun/loadRun/listRuns/listRunIds/saveCheckpoint/loadCheckpoint/listCheckpoints）。**Engine 不直接操作 fs**，Store 是磁盘唯一入口；分层契约不变（Router 只选 → Runtime 只实例化 → Engine 管生命周期）。
