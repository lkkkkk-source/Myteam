# MyTeam v1.6.2 Tool Bridge Design

> 阶段：v1.6.2 — **Agent Tool Bridge（设计）**
> 目标：让已实例化的 Agent 具备“实际使用 OpenCode 工具”的能力 —— 定义把
> `AgentRuntimeInstance` 投影为 `AgentExecutionContext` 的桥梁层。
>
> 公式：
> ```
>   Agent Runtime Instance  +  OpenCode Tools  =  可执行 Agent Context
> ```
>
> 范围与限制（本阶段强制）：
> - **不写代码 / 不实现 / 不做 Trace 设计** —— 本文是 v1.6.2 的设计文档。
> - 只设计数据模型、映射规则、权限模型、安全边界与迁移路径。
>
> 分层边界（在当前边界上不变换）：
> ```
>   Router:            只负责选择（禁止：Router 创建工具）
>   Runtime Adapter:   负责实例化（禁止：Runtime Adapter 直接执行工具）
>   Tool Bridge:       新增层，只负责 tool capability binding
> ```

---

## 1. Current Tool Model

### 1.1 MyTeam 侧已存在的能力面（只读 / 治理）

| 资产 | 文件 | 数量 | 性质 |
|---|---|---|---|
| Agent 定义 | [plugin/opencode/agent-loader.ts] → `source/prompts/**/*.md` | 30 | v1.6.1 已解析为 `AgentDefinition` |
| Agent 实例 | [plugin/opencode/agent-instance.ts] → `<project>/.team/runtime/...` | 动态 | v1.6.1 已投影为 `AgentRuntimeInstance` |
| MCP 能力 | `.ai/context/capability/mcp-registry.yaml` | 5 | 索引（context7/fetch/memory/playwright/sequential-thinking） |
| MCP 绑定 | `platform/runtime-adapter/mcp-binding.yaml` | 5 | **declaration-only，status=declared** |
| Skill 能力 | `.ai/context/capability/skill-registry.yaml` | 26 | 索引 |
| 权限政策 | `platform/runtime-execution/permission-policy.yaml` | v0.9 | Action risk → permission 映射 |
| 执行器 | `platform/runtime-execution/executor-registry.yaml` | v0.9 | executor 能力登记（不实现执行） |

### 1.2 OpenCode 侧出现给用户的工具面（Host 内置 + 插件）

OpenCode 作为 Host 提供一套内置工具（读/写/编辑/shell/bash、grep、glob、文件读取等），
以及每个 MCP 暴露的工具命名空间（如 `context7_query-docs`、`playwright_browser_*`、
`sequential-thinking_*`、`fetch_fetch`、`memory_*`）。

插件注册的 Host 工具（[plugin/opencode/index.ts]）：
- `myteam` — 单一入口：转发给既有 project-manager-agent（Router 内部）。
- `myteam.status` — 只读状��。
- `myteam.execution.admit` — 治理性准入（**不生成 Action**）。

### 1.3 当前权限系统（v1.6.2 之前）

现状是把权限挂在 **Action 执行层面**（不挂在 Agent 层面）：
- `ExecutionRequest.permission_context.risk_level` → `permission_map` → 一个权限档。
- 权限档：`workspace_write`（低）→ `process_run` → `review_required`（中）→
  `human_approval`（高）→ `explicit_user_confirmation`（critical）。
- 多层一致：`memory`、`execution` 命名空间与 `.team` 子目录（memory/execution/trace/collaboration）已在 v1.6.0 确立。

### 1.4 结论

MyTeam 已经能把一个 Agent **实例化**（v1.6.1），也有完整的 **平台级权限/执行器** 登记，
但 **“实例 → 具体某项目里能调哪些工具”的桥接还不存在** —— 这正是 v1.6.2 的空白。

---

## 2. Missing Capability

**缺失能力：Agent 实例缺少“在一段项目上下文里可用的工具集合”。**

- 现在 `AgentRuntimeInstance` 只有 `workspace / memory_namespace / permissions / instance_dir`，
  其中 `permissions` 是 v1.6.1 带入的**静态声明**（读/写/执行 的意图）。
- 但没有把它变成“针对某个 `project_root` 的、可执行的工具列表 + 绑定好的 MCP/Skill”。
- 也就是说：`AgentRuntimeInstance` 是“定义投影”，**没有“能力投影”**。

空白即要补的一层：
```
   AgentRuntimeInstance（静态）
            │  Tool Bridge（v1.6.2, 只做 capability binding）
            ▼
   AgentExecutionContext（在该项目里可执行的工具 + 权限 + MCP + Skill）
```

---

## 3. Tool Bridge Architecture

### 3.1 输入 / 输出

**输入（Tool Bridge 消费）**
- `AgentRuntimeInstance`（来自 v1.6.1 Runtime Adapter）。
- `Resolution`（`myteam_home` / `project_root` / `team_root`）。
- 能力索引：MCP registry、Skill registry（只读引用）。

**输出（Tool Bridge 产出）**
- `AgentExecutionContext` —— 一个 Agent 在某项目中的“可执行能力上下文”。

### 3.2 AgentExecutionContext 数据形态（设计）

```yaml
schema_version: 1
layer: "tool-bridge-context"
agent:            <agent 名>
instance_id:      <execution_id>:<agent>
project_root:     <项目根>            # 允许写入/读取的项目代码域
team_root:        <project_root>/.team
workspace:        <worktree/项目根>     # 工具默认工作目录
tools:
  - { tool: "read",        allowed: true }
  - { tool: "edit",        allowed: false }
  - { tool: "bash",        allowed: false }
  - { tool: "grep",        allowed: true }
  # ...
permissions:      # agent 级（见 §4）
  read:    true
  edit:    false
  execute: false
mcp:              # 绑定后的 MCP（见 §5）
  - { mcp: "context7", capabilities: ["docs-query", "code-examples"] }
skills:           # 由 AgentDefinition.skills 解析得到
  - <skill 名>...
security:         # 见 §6
  allowed_domains:   ["<project_root>", "<team_root>"]
  forbidden_domains: ["<myteam_home>", "~/.config/opencode"]
```

### 3.3 Tool Bridge 行为（设计，不实现）

Bridge 只做**绑定与投影**，不触发执行：
1. **解析工具清单**：根据 `permissions` 决定开放哪些 Host 工具（read/edit/bash/grep/glob）。
2. **绑定 MCP**：`AgentDefinition → mcp-registry → 该项目可用 MCP 子集`（见 §4/§5）。
3. **绑定 Skill**：把 `AgentDefinition.skills` 引用到的 skill 名投影到上下文。
4. **注入安全域**：把 `allowed / forbidden domains` 写入上下文，供未来执行层拦截（v1.6.3+）。
5. **产出 `AgentExecutionContext`** 并（可选）按实例持久化。

> 边界：Tool Bridge **不等于** Execution Engine。Bridge 只把“能做什么”声明出来；
> “做不做 / 什么顺序 / 何时调用”仍归 Execution（后续阶段，或平台既有 Execution Engine）。

## 4. Permission Model

### 4.1 agent 级权限（本项目设计采纳）

按 Agent 身份声明三类布尔权限，决定该 Agent 可用工具的范围：

```yaml
permissions:
  read:    true|false
  edit:    true|false
  execute: true|false
```

示例（来自需求）：
| Agent | read | edit | execute | 语义 |
|---|---|---|---|---|
| architect | ✅ | ❌ | ❌ | 只读 + 设计输出（不写代码、不执行） |
| developer | ✅ | ✅ | ✅ | 全量读改执行 |
| tester | ✅ | ❌ | ✅ | 只读 + 可执行测试 |
| reviewer | ✅ | ❌ | ❌ | 只读审查 |
| release-agent | ❌ | ❌ | ✅ | 只执行发布动作（受高级权限约束） |

### 4.2 工具 ← 权限 映射（Tool Bridge 消费）

| Host 工具 | 需要 permission | 安全域 |
|---|---|---|
| `read` / `grep` / `glob` / 查看类 | `read: true` | allowed |
| `edit` / `write` | `edit: true` | 仅 `allowed_domains` |
| `bash` / `execute` / MCP 执行类 | `execute: true` | 仅 `allowed_domains`（契约 shell 由 Host 授予，Bridge 只开关） |

> 约定：`execute: true` 意味着“允许调用会触发副作用的工具”（bash、MCP 写类）。
> 但每一种执行仍要过平台既有治理（`permission-policy` / `executor-registry` / Approval），
> Tool Bridge 只决定“这个 Agent 在这一项目里是否具备该项”，不替代 Approval。

### 4.3 与既有 Action 权限的衔接（不冲突）

- Tool Bridge 的 `read/edit/execute` 是 **agent 级能力声明**。
- 平台 `permission-policy` 的 `workspace_write / human_approval / ...` 是 **action 级风险门槛**。
- 二者是“叠加”关系：`agent 可执行(A) → action 尚需通过风险门槛(B)` → 才真正落地。
- v1.6.2 只定义 A 层；B 层沿用，不重写。

## 5. MCP Binding

### 5.1 现状

`platform/runtime-adapter/mcp-binding.yaml` 已声明 5 个 MCP → OpenCode 运行时映射
（status=declared，只声明不自动新增）。

### 5.2 映射链（设计）

```
AgentDefinition
   │  §agent-loader 解析出 capability_refs / 家族（architect/developer/tester...）
   ▼
mcp-registry.yaml（provides / agents_using / capabilities）
   │  按 agent 名反向查出该 agent 用的 MCP 及其 capabilities
   ▼
AgentRuntimeInstance（v1.6.1）
   │  Tool Bridge 合并：permission + mcp-binding 的 declared 映射
   ▼
AgentExecutionContext.mcp[]
   │  最终落到 “该实例/该项目可用的 MCP 子集”
```

### 5.3 产出示例（architect）

```yaml
mcp:
  - { mcp: "context7",           capabilities: ["docs-query", "code-examples"] }
  - { mcp: "sequential-thinking", capabilities: ["multi-step-reasoning"] }
  - { mcp: "memory",              capabilities: ["memory-persistence"] }
# fetch/playwright 不绑定（architect 不需要）
```

tester 则多绑定 `playwright`（browser-testing / e2e）、`sequential-thinking`、`memory`。

> 规则：Tool Bridge **只引用** registry 已有声明，不新增 MCP 实体、不碰 provider key、
> 不覆盖用户 opencode.json 的 mcp block（继承 runtime-adapter「declaration-only」契约）。

## 6. Security Boundary

### 6.1 允许（Allow）

| 域 | 用途 |
|---|---|
| `<project_root>` | 项目代码 —— 可读、可按 `edit/execute` 写/执行 |
| `<project_root>/.team`（team_root） | 运行状态 / memory / execution / agent-instance —— 实例持久化域 |

### 6.2 禁止（Forbid）

| 域 | 原因 |
|---|---|
| `<myteam_home>`（`source/ platform/ prompts/ agents/ registry/`） | MyTeam 平台即 Source of Truth，**只读**，禁止任何写入 |
| `<myteam_home>` 下的 `.ai/context/` 等 | 平台上下文，禁止写 |
| `~/.config/opencode` + `opencode.json` | Host 配置，一律禁止（继承 v1.0.1） |
| `.github/`、`node_modules` 外的敏感系统路径 | Host/系统级，禁止 |

### 6.3 实现层面的“守卫”来源（引用既有，不新造）

- `bridge.ts → guardHostWrite`：拦 `~/.config/opencode`（Hook 在 `tool.execute.before`）。
- 新域规则（v1.6.2 设计）：在 Bridge 产出的 `security` 内登记 `allowed/forbidden`，
  供未来执行层统一在写/执行前校验（v1.6.3 实现时使用；本阶段只登记规则）。

### 6.4 不变量（Design-Time）

- Tool Bridge **禁止直接调用任何工具**（只绑定/投影）。
- 任何工具调用必须同时满足：`agent 权限(read/edit/execute)` + `platform 治理(risk/approval)` +
  `安全域(不在 forbidden)`。
- 卸载插件的可逆性不变：工具能力在 `.team`/上下文内，删除即可回退，无 Host 残留。

## 7. Migration Plan（v1.6.2 → 后续）

### 7.1 本阶段（v1.6.2, design-only）

- [x] 定义 `AgentExecutionContext` 数据形态。
- [x] 定义 agent 级 `read/edit/execute` 权限模型。
- [x] 定义 MCP/Skill 绑定链。
- [x] 定义安全边界。
- [ ] （后续实现）编写 `tool-bridge.ts`：`AgentRuntimeInstance + Resolution → AgentExecutionContext`。

### 7.2 实现顺序建议（后续，不在本阶段实现）

1. **v1.6.3**：`tool-bridge.ts` + `AgentExecutionContext` 投影（含 permission → 工具开关）。
2. **v1.6.4**：执行层接入安全域校验（把 Bridge 的 `allowed/forbidden`
   接到写/执行工具的前置拦截）。
3. **v1.6.5+**（如需）：将 Bridge 与既有 Execution Engine / Trace 打通
   （本阶段明确**不做 Trace 设计**，留作后续独立阶段）。

### 7.3 兼容性

- 不修改 Router（仍只选择、不创建工具）。
- 不修改 v1.6.1 `AgentRuntimeInstance` 结构（Tool Bridge 只新增读入它、产出新上下文）。
- 不改变 `AgentDefinition` 解析（只新增引用 MCP/Skill 的方式）。
- 所有新产出沿用 `.team` 域，不触碰 MyTeam Home / Host。
