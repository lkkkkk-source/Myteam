# Runtime Controlled Execution Interface Layer — v0.9 Report

> 阶段：v0.9 · **Runtime Controlled Execution Interface Layer**（Governed Agent Runtime 最后一层）
> 目标：补上 `Approved Action → Controlled Execution`。将 v0.8 已批准的 Action Proposal 转换为**受治理的 Controlled Execution Request**，并连接 Quality / Observability / Rollback。
> 升级前基线：Agent=30 MCP=5 Skill=26 Workflow=8（**不变**）

## 1. Execution Layer 架构

在 v0.8 Action Approval 之上补最后一层，形成 Governed Agent Runtime：

```
... → Action Proposal → Approval
 ↓
Controlled Execution Interface   ← 本层（v0.9）
   Execution Request（只引用 approved action）
   → Approval Check → Executor（registry）→ Permission（policy）→ Sandbox（隔离）
   → Result → Quality / Observability
   → 失败则 Rollback（复用 Recovery）
 ↓
Quality → Observability → Evolution
```

- **`platform/runtime-execution/execution-schema.yaml`**：执行请求契约 + **6 条不变量（ex-1~ex-6）** + 状态机 `prepared → approved → running → completed | failed → rolled_back | cancelled`。
  - ex-1：必须引用 `status=approved` 的 Action，否则拒绝进入 running。
  - ex-5：本阶段**不实现真实执行引擎**（status 仅登记）。ex-6：不绕过 Approval / 不自动生成 Action / 不自动选 Agent / Model。

## 2. Executor Registry

`platform/runtime-execution/executor-registry.yaml`（6 个 executor，`supported_actions ⊆ action-policy.action_types`）：
code-workspace-executor / test-executor / docs-executor / deploy-executor / release-executor（rollback_support=false）/ config-executor。

## 3. Permission Model

`permission-policy.yaml`：risk → 权限，扩展 **critical** 档：
low→workspace_write ｜ medium→workspace_write+review_required（PM）｜ high→human_approval（human）｜ **critical(database_change)→explicit_user_confirmation**。权限只检查/拒绝，不代替 Approval，不降级。

## 4. Sandbox Contract

`sandbox/sandbox-schema.yaml`：隔离接口（`sandbox_id / workspace / allowed_operations 白名单 / resource_limit / cleanup_policy`），隔离类型 none / workspace-clone / temp-env / container（**本阶段只定义**）。实例 SB-0001（workspace-clone）、SB-0002（temp-env）。

## 5. Rollback Interface

`rollback/rollback-schema.yaml`：**复用已有 Recovery（v0.3.3），不重设计**。字段 `rollback_id / execution_ref / strategy / checkpoint_ref / status`；策略 artifact_restore / workspace_restore / state_restore；`checkpoint_ref` 引用 `.ai/context/recovery/checkpoints/*`。实例 RB-0001（EX-0003 failed → workspace_restore → restored）。release 类 rollback_support=false 转人工。

## 6. Runtime Integration（三者分离）

- **Runtime Context=状态 / Action=意图 / Execution=执行记录**，各自台账。
- Execution Ledger `.ai/context/runtime-execution/execution-ledger.yaml`（只增审计）：EX-0001 completed（连 quality_ref/artifact_ref）/ EX-0002 cancelled（未批准）/ EX-0003 rolled_back。task 与 runtime-context / action-ledger 对齐。
- 执行历史 `history/EX-20260921-history.yaml`：execution_metrics（duration / failure_type / rollback_count / approved_before_execution_rate=1.0）→ Observability。
