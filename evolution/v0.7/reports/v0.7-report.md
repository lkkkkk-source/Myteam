## 1. 分层定位（v0.7 在链路中的位置）

在既有各 Agent Platform 能力模块之上，建立**统一 Runtime Context 驱动的协作层**——解决"各模块各自独立、跨模块协调不可追溯"的问题：

```
User
 ↓
Router → Team → Agent → Model Recommendation → Scheduler → Execution → Quality → Observability → Evolution
        （完整：User → Router → Team → Agent → Model Recommendation → Scheduler → Execution
              → Quality → Observability → Evolution）
```

Runtime Contract 定义"谁是某段上下文的 owner、谁是只读消费者、流转路径、硬性边界"；Runtime Context（集成台账 + 各模块自有文件）记录"各模块当前在哪、是否合规"，让跨模块协调**可追溯**。

## 2. Runtime Contract 设计

- **`platform/runtime/runtime-contract.yaml`**：模块协作"宪法"。
  - **模块归属矩阵**：10 个模块各自的 `owner_agent`（有权写入）与 `reader_agents`（只读消费者）——防越权。
  - **流转路径**：`flow.sequence` = Router → Team → Agent → Model Recommendation → Scheduler → Execution → Quality → Observability → Evolution。
  - **硬性边界**：`not_implemented` = auto-execution / auto-schedule / auto-model-switching / auto-agent-selection / auto-contract-mutation。
- **`platform/runtime/runtime-context-schema.yaml`**：台账字段白名单 + `forbidden_fields`（auto_exec / auto_schedule / auto_model_switch / auto_agent_select 出现即 Contract 违规）。
- **`platform/runtime/runtime-context-template.yaml`**：台账模板（engops-lead 复制维护）。
- **`platform/runtime/snapshot/snapshot-schema.yaml`**：快照字段集 + 只读约束。

## 3. Runtime Context 设计

- **集成台账（ledger）**：`.ai/context/runtime/runtime-context.yaml`
  - 只记录 `provides`（各模块自有上下文路径）、`state`、`owner_agent`、`contract_ok`；**不复制各模块细节**。
  - 当前：`rc-refund-feature-001`（refund-feature 任务），10 个模块全部 `contract_ok=true`。
- **快照**：`.ai/context/runtime/snapshots/RC-SNAP-20260921-0001.yaml`
  - `contract_version` 变化时留底；含 `modules_summary` 只读汇总；**快照只读、不用于自动调度**。

## 5. 硬性边界（强制）

- Runtime Contract / Context 台账**只记录、只定义、只检查**；无任何自动执行 / 调度 / 切换 / 选择。
- 台账与契约由 **engops-lead（人工）维护**，禁止其他 Agent 自动改写（auto-contract-mutation = 未实现）。
- 快照只读、不可修改 / 回填；跨模块协调以人工 + 契约校验为依据。
- 不自动切换模型 / Provider / 不自动调用模型 / 不自动选 Agent；台账不驱动自动执行。
