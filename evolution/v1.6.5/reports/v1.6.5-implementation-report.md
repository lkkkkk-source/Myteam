**Store 接口（全部路径基于 `Resolution.team_root`）**：

```
execution-store.ts
├── create(res, exec)                       # 建 EX-xxx/ 骨架 + execution.yaml（status=received）
├── load(res, id)                           # 读 execution.yaml（缺失返回 null）
├── save(res, exec)                         # 只落盘；不推进状态、不校验状态转移
├── list(res)                               # 项目内全部 execution 摘要（EX- 数字升序）
├── saveRun / loadRun / listRuns            # runs/<runId>.yaml
├── saveCheckpoint / loadCheckpoint / listCheckpoints   # checkpoints/<cp>.yaml
└── saveResultArtifact / loadResultArtifacts            # result/ 文件登记 + 复制
```

## Directory Layout

```
<project>/.team/runtime/execution/EX-xxx/
├── execution.yaml     # Execution 主清单（schema_version 1）
├── plan.yaml          # Router 产物快照（本阶段只留位，不解释）
├── runs/              # AgentRun 记录（<runId>.yaml）
├── checkpoints/       # HumanCheckpoint 记录（<cp>.yaml）
└── result/            # Result Artifact（文档/产出物；可嵌套子目录）
```

## Security Verification

1. **路径穿越拒绝**：`assertValidExecutionId` 只允许 `/^EX-\d+$/`；`create()` 额外校验 execution 目录必须落在 team_root 内。
2. **MyTeam Home 禁写**：`assertNotDenied` 拦截 myteam_home 及其子路径（写入即抛错）；测试用 mtime 快照比对验证零改动。
3. **宿主配置禁写**：`~/.config/opencode` 纳入 deny 域（沿用 v1.6.3 `security.ts` 契约）。
4. **result artifact 逃逸拒绝**：目标经 `path.resolve` 归一化后必须仍位于 `<exe>/result/` 内，否则抛错。
5. **原子写**：全部写盘走 `writeAtomic`（`*.tmp` → rename），对齐 `agent-instance.ts` `persist()` 风格。
6. **无外部依赖**：纯 `node:fs` / `node:path` / `node:os`，零 npm 依赖；不 import 执行相关模块。

## Known Limitations

1. **只存不推进**：Store 不校验 status 转移合法性、不推进状态机——推进属 Execution Engine（v1.6.5 明确禁止实现）。
2. **plan.yaml 仅留位**：Router 产物快照由后续阶段写入，Store 只搬运不解释。
3. **run/checkpoint 命名由调用方给**：Store 不自动生成递增 id（如 run-0001 / cp-0001），由上层决定；避免重复写由调用方保证。
4. **result 复制语义**：工作区外文件复制进 result/（产生副本）；已在 result/ 内的文件直接登记不复制。
5. **极简 YAML**：对齐项目既有风格（顶层 key/value + `-` 列表），非完整 YAML 规范解析；含换行/复杂嵌套的内容不在本层处理。
6. **单文件写入即可丢失**：无事务/无跨文件原子性（写 execution.yaml 与写 run 是两个独立原子操作，非多文件事务）。
