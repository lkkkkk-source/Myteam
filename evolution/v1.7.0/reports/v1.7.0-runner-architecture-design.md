# MyTeam v1.7.0 Runner Architecture Design

> 阶段：v1.7.0 — **Runner Layer**（Execution → Agent 执行的桥接契约设计）。
> 前置：v1.6.0 Workspace Binding / v1.6.1 Agent Runtime Instance / v1.6.3 Tool Bridge Context / v1.6.5 Execution Persistence / v1.6.7 Execution Engine。
> 约束：**只设计，不实现**。不实现 Agent 执行体、不调用 OpenCode Tool、不实现 Trace。
> 落点：设计文档（本文件），无代码。

---

## 0. 定位

`Runner` 是 MyTeam 运行时链中 Execution Engine 与「实际 Agent 执行」之间的**桥接层**：

```
Execution Engine (v1.6.7)   ← 生命周期驱动：状态/run/checkpoint
        │  Runner 输入         （AgentRun + AgentRuntimeInstance + AgentExecutionContext + TaskInput）
        ▼
Runner (v1.7.0)            ← 执行契约：run() / execute / 结果回写 / checkpoint 触发
        │  调用适配器           （AgentExecutor 接口，可插拔，不实现）
        ▼
实际 Agent 执行体          ← 不在本层实现（消费 Model/LLM/OpenCode 运行时）
        └─ Tool Bridge (v1.6.3)  ← 唯一能力出口：AgentExecutionContext.tools → 调用许可（不绕过）
```

**一句话**：Runner 不管「Agent 怎么想」，只管「一次 AgentRun 怎么被搬上执行体、工具怎么合规地被执行体拿到、结果和错误怎么回到 Store」。

## 1. Runner Boundary

### 1.1 四层职责划分（不重叠、不穿透）

| 层 | 职责 | 拥有 | 不做 |
|---|---|---|---|
| **Execution Engine** (v1.6.7) | 生命周期：Execution 状态机、AgentRun 状态机、Checkpoint 状态机、崩溃恢复 | Store（磁盘真相） | 不启动 Agent、不执行工具 |
| **Runner** (v1.7.0) | 把一次 AgentRun 「搬上」执行体：组装 TaskInput → 调用 AgentExecutor → 收集输出/产物 → 回写 Store → 决定 NextAction；**是唯一被允许启动 Agent 的层（通过适配器接口）** | 执行调用契约 | 不实现 Agent 本身、不直接调工具、不做 Trace |
| **Tool Bridge** (v1.6.3) | 能力绑定：AgentRuntimeInstance → AgentExecutionContext（tools/permissions/mcp/skills/security） | 能力清单 + 安全域 | 不执行（工具调用由未来 Tool Bridge 调用接口承接） |
| **Agent Runtime**(v1.6.1) | AgentDefinition → AgentRuntimeInstance 投影与持久化 | 实例模型 | 不执行、不绑定能力 |

### 1.2 Runner 与相邻层的接口（唯一通道）

| 通道 | 方向 | 内容 |
|---|---|---|
| `EngineDeps` 扩展点 | Engine → Runner（反之） | Runner 调用 Engine 的 `startRun / completeRun / failRun / transition / resolveCheckpoint`，不直接碰磁盘 |
| `AgentExecutor`（本设计新增的**接口**） | Runner → 执行体 | `execute(input): Promise<AgentRunResult>` — Runner 唯一的外部执行通道 |
| `ToolInvocationPort`（契约，未来 Tool Bridge 调用接口补齐） | Runner → Tool Bridge | 工具调用请求，**不从 Runner 直连 OpenCode tool** |
| `AgentExecutionContext` | Tool Bridge → Runner | 只读能力上下文；Runner 校验 allowed/security 域 |

### 1.3 Runner 严格禁则

- ❌ 不实现 Agent 执行体（不内嵌模型推理 / 不自己循环调用 LLM）。
- ❌ 不直接调用 OpenCode tool / bash（工具一律经 ToolInvocationPort 走 Tool Bridge）。
- ❌ 不直接读/写 Store 磁盘（只经 Engine 的公开 API）。
- ❌ 不实现 Trace 事件总线 / 埋点审计（留未来独立层）。

## 2. Runner Input Model

Runner 一次执行的输入封装为 `RunnerInvocation`（命名 `run()` 的参数）。

```text
RunnerInvocation
  ├─ run            : AgentRun        ← v1.6.5 模型；本次要跑的调用（input 为任务提示）
  │
  ├─ instance       : AgentRuntimeInstance   ← v1.6.1 模型；执行上下文（prompt_source /
  │                                              workspace / memory_namespace / permissions /
  │                                              instance_dir），引用 Home 不复制
  │
  ├─ context        : AgentExecutionContext ← v1.6.3 模型；能力上下文（tools[] / permissions /
  │                                              mcp[] / skills[] / security 安全域）
  │
  └─ taskInput      : TaskInput       ← Runner 组装后的「执行输入」，见 §2.1

  （隐含） engine : EngineDeps        ← 结果回写 / 状态推进 / checkpoint 的唯一通道
```

### 2.1 TaskInput（Runner 组装，非执行体自造）

```text
TaskInput
  ├─ agent           : string          // = instance.agent
  ├─ goal            : string          // 源自 AgentRun.input（本轮任务提示摘要）
  ├─ prompt_source   : string          // 引用 myteam_home 的 prompt 文件（只读）
  ├─ workspace       : string          // = instance.workspace（已规范化）
  ├─ memory_ns       : string          // = instance.memory_namespace（team_root/memory 域内）
  ├─ permissions     : string[]        // = instance.permissions（静态白名单）
  ├─ execution_id    : string          // = run.execution_id（链路追踪 ids，非 Trace 实现）
  └─ instance_id     : string          // = instance.id
```

设计要点：

- **TaskInput 由 Runner 组装**，执行体不自行猜测输入，保证「一次 AgentRun = 一次确定性调用」。
- **引用而非复制**：prompt_source 指向 Home 文件、workspace/memory 指向项目/team 根——维持 v1.6.0 隔离。
- Runner 不做任何文件写入；写结果由结果回写层（§3）负责。

## 3. Runner Output Model

执行完成后 Runner 产出 `AgentRunResult`，并**回写** Store（经 Engine）与 result 目录。

### 3.1 输出模型

```text
AgentRunResult
  ├─ runId          : string            // = run 的 id（run-0001）
  ├─ status         : "completed" | "failed"   // 最终 run 状态
  ├─ output         : string            // 结果摘要（= AgentRun.output）
  ├─ artifacts      : Artifact[]        // §3.2
  ├─ nextAction     : NextAction        // §3.4
  └─ meta           : { started, completed, error? }  // 计时 + 失败原因（非 Trace 级埋点）
```

### 3.2 Artifacts

```text
Artifact
  ├─ name    : string            // 相对 result/ 的文件名
  ├─ path    : string            // 绝对路径（= resultDir/<name>，v1.6.5 Store 的 resultDir）
  ├─ size    : number            // 字节数
  ├─ modified: string            // 最后修改时间
  └─ kind    : "document" | "data" | "media" | "other"
```

- 文件本体落 `<project>/.team/runtime/execution/<EX>/result/`；`Artifact` 只是描述（与 v1.6.5 `ResultArtifact` 一致）。
- Runner 负责「登记」产物（把执行体产出/落盘的文件记录为 Artifact）；不负责生成产物体内容。

### 3.3 回写契约

| 情况 | Runner 动作 |
|---|---|
| `status=completed` | 调 `engine.completeRun(execution, runId, output)` |
| `status=failed`    | 调 `engine.failRun(execution, runId, errorString)` 写入 output |
| 产物已落盘         | 经 Store 的 artifact 登记（`saveResultArtifact`），Runner 不直接写 result 目录 |

### 3.4 Next Action（单 AgentRun → 执行级决策的最小句型）

```text
NextAction
  = "continue"          // 同一 Agent 还有后续轮次（下一轮 run）
  | "human_checkpoint"  // 需要人工确认（触发 §6）
  | "transition"        // 需要换 Agent / 换阶段（交给上层调度器）
  | "complete"          // 任务完成（经 Engine.complete → completed）
  | "fail"              // 失败（经 Engine.fail → failed）
```

设计要点：

- NextAction **不代表新状态**，只把 AgentRun 的结束转化为调度层可消费的最小指令。
- Runner 不自己「挑选下一个 Agent」——那属于上游 Router / 调度（v1.6.4 Scheduler Boundary 分层：Router 只选 → Runtime 只实例化 → Engine 管生命周期 → **Runner 只跑**）。
- `run()` 的副作用顺序固定：**执行 → 登记（Artifact 登记）→ 回写 Store → 返回 NextAction**，保证幂等可重放（崩溃后 `recover()` 可重新调用）。

## 4. Tool Invocation Boundary

### 4.1 原则

Runner **消费** `AgentExecutionContext.tools`，但**不绕过 Tool Bridge** 调用工具。

### 4.2 机制（ToolInvocationPort 契约）

```text
ToolInvocationPort（接口，供未来执行体经 Runner 调用）
  invoke(req: ToolInvocationRequest): Promise<ToolInvocationResult>

ToolInvocationRequest
  ├─ tool       : string          // 必须 ∈ context.tools[].tool
  ├─ source     : "host" | "mcp"
  ├─ arguments  : Record<string, unknown>   // 调用参数
  ├─ allowed    : boolean        // = context.tools 中该 tool 的 allowed（Runner 校验后用）
  └─ security   : SecurityContext // 继承自 context.security（allowed_paths/deny_paths/host_config）

ToolInvocationResult
  ├─ ok         : boolean
  ├─ value      : unknown        // 成功返回值
  ├─ error?     : string         // ok=false 时失败原因
  └─ duration   : number         // 执行耗时
```

### 4.3 Runner 的职责（校验 → 请求 → 不执行）

1. **校验**：工具名必须在 `context.tools` 中，且 `allowed=true`；若 `allowed=false`，Runner **拒绝**发起请求（不改变工具声明、不尝试绕过）。对路径类参数校验 `security.allowed_paths`（写域）与 `deny_paths`（禁域）。
2. **组装**：把请求传给 ToolInvocationPort，由 Tool Bridge 层（未来 v1.7.x 的调用接口）执行权限二次确认、绑定 MCP 解析、路径域拦截。
3. **透传**：Runner 只转发返回的 `ToolInvocationResult`，不解释、不二次加工。
4. **不绕过**：Runner 绝不直接调用 `context.tools` 挂载在 Host 上的原生 tool，也绝不自建进程执行 bash。

### 4.4 违反场景（设计必须拒绝）

| 场景 | 结果 |
|---|---|
| tool ∉ context.tools | 拒绝发起，报 error（不被允许的声明永远不可达执行） |
| allowed=false 但强行调用 | Runner 拒绝 + `failed`；不计入 tool 的 `ok` |
| path 参数越出 allowed_paths | 拒绝 + `failed`（安全域拦截，与 v1.6.3 security 一致） |
| source=mcp 但 MCP 未绑定 | 拒绝（mcp[] 无对应项） |

## 5. Error Handling

Runner 只需定义**错误如何流向 Store / 触发重试 / 触发取消**，不实现 Trace。

### 5.1 错误分类

| 类别 | 含义 | Runner 行为 |
|---|---|---|
| **tool_error** | ToolInvocationResult.ok=false | 视重试策略决定的**可重试**错误；输出记入 output |
| **agent_error** | AgentExecutor 自身抛错（模型错误 / 提示错误 / 适配器错误） | 不可重试，`failRun`；回写 error |
| **timeout** | 超过 `timeout_ms`（按 agent/run 配置） | 按 §5.3 |
| **cancel** | 收到用户/调度的取消信号 | 按 §5.4 |
| **assertion_error** | 状态非法（Engine 抛 EngineTransitionError 等） | 吞并记日志，`failRun`；不外泄裸异常 |

### 5.2 tool 失败

- Runner 持有**内置重试策略**：`max_retries`（默认 2）+ 指数退避；只对 `tool_error` 重试。
- 重试超限 → 当次 run `failRun`；不静默吞掉。
- 所有失败信息写入 `AgentRun.output`（结果摘要），确保磁盘可回溯（非 Trace）。

### 5.3 timeout

- `run()` 必须遵守 `AgentExecutor` 调用传入的 `timeout_ms`（来自 Agent 定义 / Runner 配置）。
- 超时 → 发出**取消信号**（见 §5.4）→ 若执行体未响应则在 `hard_timeout_ms` 后强制判 `failRun`（原因注明 timeout）。
- Runner 不杀死进程（宿主级进程管理不归它管）；只停止本次调用并回收。

### 5.4 cancel

- `ExecutorContext` 携带 `AbortSignal`（宿主取消信号）。
- line：收到信号 → 立即停止**本次调用**（不等执行体优雅退出确认）→ 状态转 `paused` 或 `failed`（由调度/用户选定；默认 `paused` 便于恢复）。
- 取消不自动删 AgentRun；保留 run 记录供恢复（幂等）。

### 5.5 错误 → 状态映射

| 事件 | Execution status | Run status |
|---|---|---|
| tool 重试后仍失败 | （按上层：可 pause / 可 fail） | failed |
| agent_error | failed | failed |
| timeout | 可 paused（可重试一次） | failed（本次超时） |
| cancel（用户） | paused（默认，可 resume） | 保留 run |

## 6. Human Checkpoint Integration

### 6.1 触发主体

Runner 在**执行过程中**判定「需要人工决策」时产生 checkpoint（如：高危操作、需要改方向、产物确认）。它通过调用 Engine 完结 checkpoint，而不是替调度者/用户做决定。

### 6.2 流程（Runner 视角）

```
run() 进行中
   └─ 判定 "需要人工确认"（可配置策略 / Agent 定义标注 humans_in_loop）
         └─ Runner 创建【未响应】HumanCheckpoint（cp-NNN，type ∈ continue/modify/reject）
               └─ 经 Engine.transition → awaiting_confirmation
                     └─ Engine.resolveCheckpoint(continue|modify|reject)  （由外部触达，非 Runner 自答）
                           └─ 结果 map 成 NextAction:
                                 continue → 同 Agent 新 run（继续）
                                 modify   → 带 resolved 的新 run（改方向）
                                 reject   → fail / complete（视策略）
```

### 6.3 关键设计点

- **Runner 只产 checkpoint，不答 checkpoint**（「*机不自动通过*」沿用 v1.6.5；Runner 不调用 `resolveCheckpoint`）。
- `type`/`message`/`options` 由 Runner 从**调度上下文**组装（何时该问人，由上层 Agent 定义/安全策略决定，Runner 不臆断）。
- 已响应后 Runner 由 `resolveCheckpoint` 返回值读出 `resolution`，据 §6.2 转 NextAction——一条 `awaiting_confirmation → ready → running` 的持有，保持状态与 run 一致。
- 兼容 v1.6.7：`modify → planning`（修改方向后回到 planning）、`continue → ready → running`（继续）、`reject → failed`（否决）。

### 6.4 双通道完整性

- 磁盘通道：checkpoint 经 Engine.create/读取落到 Store（`checkpoints/` 目录），Runner 只读写对象不碰 fs。
- 运行时通道：awaiting_confirmation 状态由 Engine 维护；Runner 在运行循环中**观测**该状态阻塞，不主动轮询写死。

## 8. 交付边界

| 项 | 状态 |
|---|---|
| Runner Boundary / Input / Output / Tool 边界 / 错误 / checkpoint 设计 | ✅ 本设计完成 |
| Agent 执行体（模型循环 / LLM 调用） | ❌ 不实现 |
| 真实工具调用（经 Tool Bridge 的下行调用接口） | ❌ 不实现（仅定义 ToolInvocationPort 契约） |
| Trace 事件总线 | ❌ 不实现 |
| 直接读写 Store / 绕过 Engine | ❌ 禁止 |
