## 2. New Files — 核心数据模型

### AgentExecutionContext（`context.ts`，设计 §1）
```
{
  schema_version: 1,
  layer: "tool-bridge-context",
  agent_instance: AgentRuntimeInstance,   // 原样携带，不改字段
  workspace,                              // = inst.workspace
  tools: ToolDeclaration[],               // host + mcp 声明（含 allowed/reason）
  permissions: AgentPermission,           // { read, edit, execute }
  mcp: McpCapability[],                   // 绑定 MCP 能力（引用 registry）
  skills: string[],                       // skill 名（引用 AgentDefinition.skills）
  security: SecurityContext,              // allowed_paths / deny_paths
  persistence_target,                     // <team_root>/runtime/context/<agent>/...
}
```

### 持久化
`<project_root>/.team/runtime/context/<agent>/agent-execution-context.yaml`
（与 v1.6.1 的 `runtime/agent-instance/` 并列；**绝不写 MyTeam Home**）

## 3. Data Model — Resolvers

### Permission Resolver（`permission-resolver.ts`，设计 §3）
按 agent 名称/角色关键词归类（先命中者优先），生成只读的权限模型，**不执行检查**：

| Agent 族 | read | edit | execute | 说明 |
|---|---|---|---|---|
| developer/implement/coder/engineer | ✓ | ✓ | ✓ | 开发者全开放 |
| tester/debug/verifier/qa | ✓ | ✗ | ✓ | 可读 + 可执行，不直接改码 |
| release/publish/deploy/engops | ✗ | ✗ | ✓ | 只执行发布动作 |
| architect/planner/lead/analyst/review/writer/docs/pm... | ✓ | ✗ | ✗ | 只读（设计产出走文档） |
| **默认（未知）** | ✓ | ✗ | ✗ | 最小权限，安全兜底 |

### Tool Resolver（`tool-resolver.ts`，设计 §2）
- host 工具：`read/grep/glob`←read；`edit/write`←edit；`bash`←execute。
- mcp 工具：按绑定 MCP 声明为 `mcp:<namespace>`，后缀 `allowed/reason` 静态说明。
- 产出 `ToolDeclaration[]` —— 只声明，不触发。

### MCP Resolver（`mcp-resolver.ts`，设计 §4）
链路：`AgentDefinition → mcp-registry → AgentRuntimeInstance → AgentExecutionContext`。
- 极简 YAML 解析（无外部依赖，对齐 agent-instance 风格），**只读** registry。
- `agents_using` 映射存在时才绑定；输出为 `McpCapability[]`，**不新增 MCP / 不改配置**。
- Skill：优先取 `AgentDefinition.skills`，缺省回退 skill-registry。

### Security Context（`security.ts`，设计 §5）
```
allowed_paths: [ project_root, team_root ]     // 允许读/写/执行
deny_paths:    [ myteam_home, ~/.config/opencode ]  // 一律只读/禁写
```
提供 `isDenied()` 工具（执行层在后续阶段接入；本阶段仅生成+可查询）。

## 6. Known Limitations

1. **只做声明，不做执行**：`tools[].allowed` 与 `isDenied()` 是能力/安全登记，真正的调用拦截仍属后续执行层（Execution State / Runner）。
2. **权限按名称关键词归类**：`PERMISSION_PROFILES` 为启发式；极端命名可能落入默认最小权限（安全兜底，可人工扩展表项/覆盖）。
3. **MCP 能力子集仅为绑定投影**：`capabilities` 来自 registry 声明，未验证 MCP 服务器实际在线状态（需执行层探测）。
4. **YAML 为“类 YAML”可读文本**：沿用现有极简渲染风格（无外部 YAML 库），适合人读+外部工具二次解析，不作为强类型 schema。
5. **每次 build 重新读取 registry + 全量解析 30 prompt**：演示/冒烟路径可接受；生产可在上层做缓存。
6. **持久化为单 agent 单文件**：每个 agent 独立 `<agent>/agent-execution-context.yaml`，多个 agent 不互相覆盖；跨 execution 由目录维度天然隔离。
