# Agent Prompt Evolution Execution — v0.6.6 Report

> 阶段：v0.6.6 · Agent Prompt Evolution Execution（跨 Agent 批量演进）
> 目标：将 Agent 持续进化机制从「单 Agent 闭环」扩展到「批量闭环」，一次进化 3 个 Agent，验证机制可规模化。
> 升级前基线：Agent=30 MCP=5 Skill=26 Workflow=8
> 状态：完成

## 1. Agent 选择原因

- 本阶段升级 **java-architect、java-reviewer、java-tester**（批次 B-066-01），并**复核 java-developer**（v0.6.5 已 released）。
- 理由（跨 Agent 一致演进）：
  - 三者与 java-developer 构成 Java 核心执行链（architect 前置分析 → developer 编码 → tester 验证 → reviewer 审查），进化收益可叠加。
  - v0.6.3 审计已识别三者各自差距，但 v0.6.5 仅闭环了 developer；其余差距仍在。
  - 外部 `external/agency-agents/` 有高质量参考（architect / code-reviewer / reality-checker / test-results-analyzer）。
  - 验证 v0.6.5 建立的机制可**规模化**：同批次多 Agent 各自 Proposal → Benchmark → Applied → released。

## 2. 与 v0.6.5 的机制扩展

- v0.6.5：单 Agent benchmark（BM-065-01）。
- v0.6.6：**multi-agent benchmark（BM-066-01）**——同一重构场景（订单服务拆分）同时施加到 4 个 Agent。
- 新增「版本注册表 + 进化状态机 + 批量升级 + 回滚登记」三层发布治理，并把发布闭环的读取职责下放给 PM / health / engops-lead。

## 3. Prompt 差异（v1 vs v2）

| Agent | 核心差距（v1） | v2 新增 | 参考来源 |
|-------|----------------|---------|----------|
| java-architect | 结论无佐证、越界只读 | Evidence Output（模块/文件/行引用）+ Scope Self-Check（read-only 对抗）+ 决策/探索分离 + 最小充足设计 | engineering-*-architect |
| java-reviewer | 论断无证据、遗漏维度 | 证据优先（file:line+置信度）+ 反遗漏 bias + severity-gated 放行优先级 + 误报自检 | engineering-code-reviewer / reality-checker |
| java-tester | 报告缺证据、归属臆断 | 证据收集（命令输出/异常栈/覆盖率）+ 根因归属证据链 + 反幻想（default-to-failed） | testing-reality-checker / test-results-analyzer |

三者为**纯加法**：保留全部系统层协议（Context / Memory / Artifact metadata / Quality Gate / Failure handling），无删除，不复制外部内容（仅转写为本平台协议）。

## 最终目标达成

建立了可规模化的 **Agent 持续进化机制**：

- 不是增加 Agent 数量（Agent 稳定在 30），而是让已有 Agent 通过外部研究 → Proposal → 评审 → Benchmark → 评估 → 合并 持续提升。
- 从「单 Agent 闭环」扩展到「批量闭环（B-066-01）」，以 multi-agent benchmark 统一衡量跨 Agent 一致演进。
- 通过 version-registry + evolution-state + 回滚登记 + 三层治理（engops-lead 发布 / health 一致性 / PM 状态读取），机制具备**可回滚、可追溯、可治理**的规模化基础。
- 全程不自动安装、不自动替换、不复制外部内容（仅参考 + 转写为本平台协议）。
