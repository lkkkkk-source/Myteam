| `index.ts` | 模块出口 |
| `test/model-adapter.test.ts` | 21/21 PASS |

### 1.2 契约要点

- **唯一推理入口**：`ModelAdapter.complete(req: ModelRequest): Promise<ModelResponse>`；抽象层无任何供应商专有字段（M-3）。
- **`ModelRequest`**：`{ prompt: ExecutionPrompt; expects: "text"\|"json"; signal?; timeout_ms? }`。
- **`ModelResponse`**：`{ ok; text; usage?; finish_reason: "stop"\|"length"\|"tool_use"\|"error"; error_kind?; error_detail? }`。
- **`AgentErrorKind`**：与设计 §8.2 完全对齐（model_error / timeout / invalid_response / context_overflow / cancel / tool_denied / tool_error / agent_error）。

### 1.3 NullModelAdapter（默认实现，M-1/M-2）

- **不联网**：无 fetch / http / sdk。
- **无 Key**：不读 `process.env`、不落盘凭据（静态扫描断言）。
- **确定性**：同请求 → 同响应；`text` 模式回显 `goal`，`json` 模式输出 `{"kind":"answer","text":goal}`。
- **取消语义**：`signal.aborted` → `{ ok:false, error_kind:"cancel", finish_reason:"error" }`。
- **可注入**：构造函数可选 `responder`（仅测试/装配定制，不涉及网络）。

### 1.4 测试覆盖

契约形状 / text+json 模式 / 确定性 / 取消 / responder 注入 / **静态源码扫描（无 fetch、无 http(s)、无 axios/openai/anthropic、无 process.env、无 api_key/authorization/bearer、无 writeFile）**。

### 3.2 解析产物（untrusted 中间表示）

| 变体 | 字段 | 不变量 |
|---|---|---|
| `answer` | `text` / `artifacts?` / `truncated?` | 文本非空 |
| `tool_calls` | `calls[]` / `note?` | 每项已过结构校验，**不含合法性判定** |
| `checkpoint` | `message` / `options?` / `truncated?` | message 非空 |
| `invalid` | `reason` / `errorKind` / `truncated?` | 一切解析失败**折叠至此，不抛异常** |

### 3.3 解析规则（§5）

- **R-1 严格模式**：`expects='json'` 必须合法 JSON 且外层为对象。
- **R-2 结构校验**：`tool` 非空字符串、`arguments` 普通对象、`calls` 非空且 ≤ 上限。
- **R-3 不信任字段**：合法性/权限交给 ActionValidator（测试显式断言 R-3）。
- **R-4 无执行**：纯转换；静态扫描断言无 fs / http / sdk / `.invoke(` / writeFile / process.env / 随机时间。
- **R-5 安全截断**：`MAX_RESPONSE_RAW_LENGTH=1_000_000` 硬截断；`MAX_RESPONSE_TEXT_LENGTH=100_000` 字段截断；`MAX_TOOL_CALLS=64` 条数上限。

### 3.4 确定性

`parse()` 纯函数：同输入 → 同输出（测试断言 JSON 逐字节一致）。

### 4.3 产物与 Fail-Closed（§9.3 SX-6）

- `ok=true` answer / checkpoint → 透传，**无 requests**。
- `ok=true` tool_calls → `requests[]` 全部通过，每项携带完整 `security` 快照。
- `ok=false` invalid → 解析失败透传。
- `ok=false` tool_calls → **任一拒绝 → 整批不产生 requests**（不降级、不绕过）；`rejected[]` 保留原始模型意图 + 逐项 `verdicts[]` 审计。

### 4.4 隔离

## 5. Phase 3 AgentExecutor V2（`runtime/agent-executor/`）

### 5.1 交付

| 文件 | 内容 |
|---|---|
| `agent-executor.ts` | **改写**：`AgentExecutorImpl` 从占位回显升级为完整 Execution Pipeline |
| `index.ts` | 出口补充（+ `AgentError` / `buildFailure` / `collapseError`） |
| `error-model.ts` | 新增：执行层错误模型（§8） |
| `test/agent-executor.test.ts` | 改写：19/19 PASS（覆盖 8 场景） |

### 5.2 内部时序（设计 §2.3 落地）

```
AgentExecutorImpl.execute(taskInput, signal)
  1. validateTaskInput(taskInput)                 // instance_id/agent/workspace/goal/context 一致性
  2. 取消检查（signal.aborted → cancel）
  3. PromptAssembly.assemble({taskInput,context,instance})   // §3
  4. ModelAdapter.complete({prompt, expects:"json", signal})  // §4
       ├─ 取消优先（§8.4）→ cancel
       └─ modelResponse.ok=false → error_kind 透传
  5. ResponseParser.parse(modelResponse)          // §5
  6. ActionValidator.validate({parsed, context})  // §6 唯一放行闸门
       └─ !ok → Fail-Closed 折叠（不产生 requests）
  7. dispatchValidated(validated)                 // answer / checkpoint / tool_calls
       └─ tool_calls → invokeToolCalls()：逐项 toolPort.invoke()（单轮 §6.4）
  catch-all → collapseCatch()                    // §8 折叠，不外泄裸异常
```

### 5.3 关键实现

- **依赖注入**：`AgentExecutorDeps` 新增 `modelAdapter?` / `responseParser?` / `actionValidator?`；未注入 → NullModelAdapter / 默认 Parser / 默认 Validator（M-2）。
- **唯一工具入口（SX-1）**：执行体只持有 `deps.toolPort`（`ToolInvocationPort`）；不 import host-port / tool-adapter / node:fs（除注释引用）/ 网络 / SDK。
- **单轮限制（§6.4）**：一次 `execute()` 至多一轮 tool_calls 批处理 + 汇总；不做跨轮自主规划。
- **checkpoint 分派（§7）**：`checkpointRequested=true` 时如实填写 `checkpointMessage` / `checkpointOptions`（C-2 兜底不覆盖：模型给出 options 原样传递，空数组不塞默认值）。
- **工具失败折叠**：`result.ok=false` → `tool_error`（`error_kind` 非 tool_error 时映射 `tool_denied`），整批失败，不旁路。

### 5.4 测试覆盖（8 场景）

1. execute 成功（ok=true / output=goal）
2. instance_id 不匹配（ok=false / assertion_error）
3. goal 为空（ok=false / assertion_error）
4. 取消信号（ok=false / cancel）
5. 工具边界（成功路径不触碰 toolPort）
6. 模型产出 tool_calls → 经 toolPort 下发（注入 responder + 放行 validator）
7. toolPort 失败 → 折叠 `[tool_error]`
8. ActionValidator 拒绝 → Fail-Closed（`[invalid_response]`，toolPort.invoke **未被调用**）

## 7. Error Model（`runtime/agent-executor/error-model.ts`，§8）

### 7.1 类别（与设计 §8.2 完全一致）

`model_error | timeout | invalid_response | context_overflow | cancel | tool_denied | tool_error | agent_error`（定义于 `model/types.ts`）。

### 7.2 折叠实现

| 符号 | 语义 |
|---|---|
| `AgentError` | 带 `kind` 的执行体内部归一异常（显式上抛） |
| `buildFailure(kind, detail)` | 恒 `ok=false`、`error: "[<kind>] <detail>"`、不填 checkpoint 字段（E-4 / C-3） |
| `collapseError(e)` | 任意异常 → 失败结果（默认 `agent_error`） |
| `collapseCatch(e, signal)` | execute() catch-all：AgentError → 分类透传；RunnerValidationError → `agent_error`；RunnerError → `cancel`；AbortError / signal.aborted → `cancel`；其余 → `agent_error` |

### 7.3 优先级（§8.4 已落实）

`cancel` 优先于一切：execute() 在 model completion 前后、tool invocation 期间均检查 `effectiveSignal?.aborted` → `cancel`。

### 7.4 不变量

E-1 不外泄裸异常（catch-all）✓ · E-2 只用枚举值 ✓ · E-3 可诊断（error 附人读细节，不含凭据）✓ · E-4 不吞错（失败恒 ok=false）✓。

## 10. Known Limitations

| # | 限制 | 说明 / 后续归属 |
|---|---|---|
| 1 | **单轮 tool-call 执行** | 一次 `execute()` 至多一轮工具批处理 + 汇总，无跨轮自主规划（设计 §6.4）；Multi-Agent Planning 属 v1.9+ OUT。 |
| 2 | **无真实模型供应商** | ModelAdapter 仅为抽象 + Null 实现；真实适配器需上层部署显式注入（含 API Key 环境策略，另行设计评审）。 |
| 3 | **无 trace / 执行埋点** | `RunnerMeta` 仅诊断标注，非 Trace Event Bus（设计 v1.8.5 OUT）。 |
| 4 | **checkpoint_id 占位** | `mapRunnerResultToEngineAction` 仍用 `"cp-0001"` 占位，实际 id 由 `saveCheckpoint` 分配（设计 §7.5 注释，现状沿用）。 |
| 5 | **工具结果不做二次推理** | 工具返回值仅汇总进 output 文本；模型不「看到结果再决策」（与 #1 同源，属 v1.9+）。 |
| 6 | **安全域判定为字符串域** | allowed/deny 用规范化路径前缀匹配，不解析符号链接 / 不触碰文件系统（设计 §6.2 注，纵深防御下游仍保留 ToolAdapter/HostPort/Store 层）。 |
| 7 | **无 long-term memory / agent discovery** | 跨执行记忆与自动发现属 v1.9+ / 未来（设计 §10.2）。 |
| 8 | **无真实工具下行** | 全链路经 `ToolInvocationPort` mock 验证；真实 ToolAdapter/HostPort 已在 v1.7.3 独立测试通过，集成到 host 属上层装配。 |
| 9 | **取消语义依赖 AbortSignal 协作** | NullModelAdapter 仅在入口检查；真实适配器需自行配合 signal/timeout（M-4 契约已声明）。 |
| 10 | **错误可诊断性有限** | `buildFailure` 错误串为 `[<kind>] <detail>` 单行文本；无结构化 error 对象（AgentExecutorResult 契约无 error_kind 字段，设计 §8.3 落点如此）。 |
