## 2. Response Parser（`runtime/response-parser/`）

### 2.1 解析产物（`types.ts`）

`ParsedAgentResponse`（union）关键不变量：

| 变体 | 字段 | 不变量 |
|---|---|---|
| `answer` | `text` / `artifacts?` / `truncated?` | 文本非空；artifacts 仅限字符串数组 |
| `tool_calls` | `calls[]` / `note?` | 每项 `RawToolCall` 已过结构校验 |
| `checkpoint` | `message` / `options?` / `truncated?` | message 非空 |
| `invalid` | `reason` / `errorKind` / `truncated?` | **不抛异常，一切失败折叠到此处** |

`RawToolCall`：`{ tool, arguments, source? }` —— 仅描述模型意图，**不含合法性判定**。

上限常量（防 DoS）：
- `MAX_RESPONSE_TEXT_LENGTH = 100_000` —— 单字段文本截断上限（可经 `options.maxTextLength` 覆盖）。
- `MAX_RESPONSE_RAW_LENGTH = 1_000_000` —— 原始响应硬截断上限（超限先截断，JSON 残缺则 invalid）。
- `MAX_TOOL_CALLS = 64` —— 单次 tool_calls 条数上限（超出 → invalid）。

### 2.2 解析规则（`parser.ts`）

| 规则 | 实现 |
|---|---|
| R-1 严格模式 | `expects='json'` 必须是合法 JSON 且外层为对象；数组 / 标量 / 语法错误 → `invalid` |
| R-2 结构校验 | `calls[].tool` 必须非空字符串；`arguments` 必须普通对象；`calls` 非空且 ≤ 上限 |
| R-3 不信任字段 | 解析器对「未声明 / 不允许 / 越域」工具照常产出 `tool_calls`（合法性交给 ActionValidator，测试显式断言） |
| R-4 无执行 | 纯转换；静态扫描断言无 `fs / http / sdk / .invoke( / writeFile / process.env / 随机时间` |
| R-5 安全截断 | raw 超 `1M` 先截断（JSON 残缺 → invalid+truncated）；字段超上限截断并置 `truncated=true` |
| 模型失败 | `response.ok=false` → 直接 `invalid`，`error_kind`/`error_detail` 透传 |

### 2.3 确定性

`parse(response, options)` 为纯函数：相同输入 → 相同输出（测试断言 JSON 序列化逐字节一致），无字段、无状态。

## 3. Action Validation（`runtime/action-validator/`）

### 3.1 核心命题

**模型输出不能直接执行。** `ParsedAgentResponse.tool_calls` 只是模型意图；必须逐项校验通过后才产出 `ToolInvocationRequest`（设计 §6.1）。本模块是执行层**唯一放行闸门**，纯计算、只读消费 `AgentExecutionContext`。

### 3.2 校验项（§6.2，逐项映射）

| # | 检查项 | 失败分类 | 依据 |
|---|---|---|---|
| 1 | 工具已声明（`tool ∈ context.tools[]`） | `invalid_response` | 唯一合法工具集 |
| 2 | 来源一致（模型声明 `source` 时须与声明一致；缺省取声明值） | `invalid_response` | host / mcp 归属 |
| 3 | 权限允许（`decl.allowed === true`） | `tool_denied` | Permission Model |
| 4 | 安全域（路径类参数 ∈ `allowed_paths` ∉ `deny_paths`） | `tool_denied` | Security Context |
| 5 | 宿主配置黑名单（`~/.config/opencode/**`，最高优先） | `tool_denied` | Host 隔离 |
| 6 | 参数形状（tool 非空 / arguments 为对象，纵深复查） | `invalid_response` | 结构完整 |

路径类参数识别：key 命中 `read/write/edit/path` 且值为非空字符串；非路径参数（`command/pattern` 等）不受路径域约束。

### 3.3 产物（`ValidatedActions`，Fail-Closed）

| 分支 | 内容 | 不变量（§9.3 SX-6） |
|---|---|---|
| `ok=true` `answer` / `checkpoint` | 透传 | 无工具动作，不产生 requests |
| `ok=true` `tool_calls` | `requests[]` + `calls[]` + `verdicts[]` | **全部通过**；每项 request 携带完整 `security` 快照 |
| `ok=false` `invalid` | `reason` / `error_kind` | 解析失败透传 |
| `ok=false` `tool_calls` | `rejected[]` + `verdicts[]` | **任一拒绝 → 整批不产生 requests**（不降级为直连/绕过） |

逐项审计：`ActionVerdict{ tool, ok, passed[], error_kind, reason }` 覆盖每个调用；被拒项在 `RejectedToolCall{ raw, error_kind, reason }` 中保留原始模型意图。

### 3.4 隔离 / 安全边界（§9.1 SX-3）

- 静态扫描断言：无 `fs / http/net / host-port / tool-adapter` import、无 `.invoke(`、无 `writeFile`、无 `Date.now/Math.random`、**无对 `ctx.tools[].allowed` / `security` 的写操作**（SX-2 只读消费）。
- 安全域 / 宿主黑名单判定为**纯字符串计算**（`normPath` + 前缀匹配），不触碰文件系统，不依赖磁盘状态。
