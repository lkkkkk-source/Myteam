v1.8.3 已把「单次执行」的全部零件装配完成，`createRuntime()` 是唯一装配点，

```ts
async execute(taskInput, signal) {
  this.validateTaskInput(taskInput);
  if (effectiveSignal?.aborted) return this.failure("cancel", "...");
```

## §2 Agent Execution Layer 总体设计

### 2.1 设计原则

| 原则 | 说明 |
|---|---|
| **P-1 接口不变** | 对 Runner 仍只暴露 `AgentExecutor.execute(taskInput, signal)`；外部契约零变更。 |
| **P-2 内部可插拔** | Prompt Assembly / Model Adapter / Parser / Planner 均为可替换单元（依赖注入）。 |
| **P-3 唯一工具入口** | 执行体生成的任何工具动作**只能**经 `toolPort.invoke()`；不存在直连 HostPort/宿主。 |
| **P-4 只读投影消费** | 只消费 `TaskInput` / `context` / `instance`，绝不修改权限或能力声明。 |
| **P-5 无真实 Key** | Model Adapter 为抽象接口 + 可注入实现；本阶段默认实现**不联网**、不读 Key。 |
| **P-6 Prompt 单一来源** | Agent prompt 永远来自 MyTeam Home（`instance.prompt_source`）；项目内不落副本。 |
| **P-7 失败折叠** | 任何异常折叠为带分类的失败 `AgentExecutorResult`，不外泄裸异常（沿用现状）。 |

### 2.2 内部模块拆分（设计，不实现）

```
runtime/agent-executor/
├── agent-executor.ts        // AgentExecutorImpl（编排单元，接口不变）
├── prompt-assembly.ts       // §3：从 MyTeam Home 装配最终执行 Prompt
├── model-adapter.ts         // §4：Model Adapter 抽象 + 响应模型
├── response-parser.ts       // §5：模型输出 → 结构化（Action / Answer）
├── action-planner.ts        // §6：结构化 → ToolInvocationRequest[]（校验后交给 Runner）
├── error-model.ts           // §8：执行层错误分类 → AgentExecutorResult
└── index.ts                 // 出口
```

> 说明：模块边界为**设计建议**。是否合并文件由实现阶段决定；**接口契约**以本设计为准。

### 2.3 执行体 v2 内部时序（设计）

```
AgentExecutorImpl.execute(taskInput, signal)
  1. validateTaskInput(taskInput)                      // 沿用现状校验
  2. PromptAssembly.assemble(taskInput)                // §3 → ExecutionPrompt（含 prompt_source 引用）
  3. ModelAdapter.complete(prompt, {signal})           // §4 → ModelResponse（文本/结构化）
  4. ResponseParser.parse(modelResponse)               // §5 → ParsedAction（answer | tool_calls | checkpoint）
  5. ActionPlanner.validate(parsedAction, context)     // §6 → 校验工具∈context.tools & allowed & 域
  6. 若含 tool_calls:
        for req of requests: deps.toolPort.invoke(req) // 唯一工具入口（Runner 已二次校验）
        汇总 tool results → 回到步骤 3（若有后续推理轮次）或产出 final answer
  7. 产出 AgentExecutorResult{ ok, output, artifacts, checkpoint* }   // §7 完整传递
  8. 任何异常 → error-model 映射（§8），折叠为失败结果
```

> 步骤 6 的「多轮」范围：v1.8.4 **只做单轮 tool-call 执行**（一次模型回复 → 一批工具动作 → 汇总），
> 不做自主多步规划循环（属 Multi-Agent Planning，§10 OUT）。

## §3 Prompt Assembly

### 3.1 目标

把静态 Agent 定义（MyTeam Home）+ 运行投影（`TaskInput`）+ 可用能力清单（`context`）
装配为**模型执行所需的最终 Prompt**。这是本阶段题干要求的「最终执行 Prompt」产出。

### 3.2 输入（全部只读）

| 来源 | 字段 | 用途 |
|---|---|---|
| `AgentRuntimeInstance` | `prompt_source` | **prompt 文件引用（MyTeam Home 内，绝对路径）** |
| `AgentRuntimeInstance` | `agent` / `role` / `memory_namespace` | 身份与记忆命名空间标注 |
| `TaskInput` | `goal` | 本轮任务 |
| `TaskInput` | `workspace` / `memory_ns` / `permissions` / `execution_id` / `instance_id` | 环境与追踪标识 |
| `AgentExecutionContext` | `tools[]`（tool/source/allowed/reason） | **能力清单（供模型知晓可调用项）** |
| `AgentExecutionContext` | `security`（allowed/deny/host_config/myteam_home） | 边界声明（只声明，不泄漏为可写目标） |

### 3.3 Agent Prompt 来源（强制）

> **Agent prompt 仍来自 MyTeam Home。禁止复制 prompt 到项目。**

- prompt 正文 = 读取 `instance.prompt_source` 指定文件（`<myteam_home>/source/prompts/**/<agent>.md`）。
- 该路径由 `agent-loader.ts` → `agent-instance.ts` 投影而来（`prompt_source` 为**路径引用**，非内容副本）。
- Prompt Assembly **不得**把 prompt 内容写入 `<project>/.team/**`；运行时仅在内存中拼接。
- 若需留痕，只登记 **`prompt_source` 路径 + 摘要 hash**（可选，且 hash 非内容副本、不可逆取回原文）。

### 3.4 装配产物：ExecutionPrompt（设计类型）

```ts
interface ExecutionPrompt {
  /** 引用（绝不复制）：来自 instance.prompt_source。 */
  prompt_source: string;
  /** 身份段：agent / role（来自 instance）。 */
  identity: { agent: string; role: string };
  /** 任务段：goal（来自 TaskInput）。 */
  goal: string;
  /** 能力段：可用工具（来自 context.tools，仅 allowed=true 的项）。 */
  capabilities: { tool: string; source: "host" | "mcp"; reason: string }[];
  /** 约束段：workspace / memory_ns / permissions（声明用）。 */
  constraints: { workspace: string; memory_ns: string; permissions: string[] };
  /** 装配后的消息序列（供 Model Adapter 消费；schema 由适配器约定）。 */
  messages: { role: "system" | "user"; content: string }[];
}
```

### 3.5 装配规则

| 规则 | 说明 |
|---|---|
| **P-A1 引用优先** | `prompt_source` 作为引用携带；正文按需读取，不落项目。 |
| **P-A2 只列 allowed** | `capabilities` 只含 `allowed=true` 的工具；`allowed=false` 项**不进入**模型上下文（避免诱导越权）。 |
| **P-A3 边界不暴露写目标** | `deny_paths` / `host_config` / `myteam_home` 不写入 prompt（仅内部校验用），防止模型以「写配置」为手段。 |
| **P-A4 无副作用** | 装配纯内存；不写盘、不调用工具、不联网。 |
| **P-A5 可测确定性** | 相同输入 → 相同 `ExecutionPrompt`（无随机、无时钟依赖，除可选 trace id）。 |

## §4 Model Adapter

### 4.1 目标

为执行体提供**模型推理的抽象边界**。本阶段**只定义接口**，不接入真实 API Key、不选择供应商。

### 4.2 抽象接口（设计）

```ts
/** 模型推理请求（适配器无关）。 */
interface ModelRequest {
  /** 由 Prompt Assembly 产出的执行 prompt。 */
  prompt: ExecutionPrompt;
  /** 期望产物：'text' | 'json'（parser 决定解析策略）。 */
  expects: "text" | "json";
  /** 取消信号（透传宿主）。 */
  signal?: AbortSignal;
  /** 超时上限（毫秒；0/缺省 = 无）。 */
  timeout_ms?: number;
}

/** 模型推理响应（适配器归一后）。 */
interface ModelResponse {
  ok: boolean;
  /** 原始文本（text 或 JSON 字符串）。 */
  text: string;
  /** 供应商可辨识的用量（可选；不强制）。 */
  usage?: { input_tokens?: number; output_tokens?: number };
  /** 完成原因：stop | length | tool_use | error（归一）。 */
  finish_reason: "stop" | "length" | "tool_use" | "error";
  /** ok=false 时的错误分类（见 §8）。 */
  error_kind?: AgentErrorKind;
  error_detail?: string;
}

/** 模型适配器 —— 执行体唯一推理入口。 */
interface ModelAdapter {
  complete(req: ModelRequest): Promise<ModelResponse>;
}
```

### 4.3 本阶段实现约束（硬性）

| 约束 | 说明 |
|---|---|
| **M-1 无真实 Key** | 默认 `ModelAdapter` 实现为 **NullModelAdapter**（返回固定/回显响应），**不读环境变量、不发网络请求**。 |
| **M-2 可注入** | 真实适配器由上层显式注入（`AgentExecutorDeps.modelAdapter`）；未注入 → 用 Null 实现（可测）。 |
| **M-3 无供应商绑定** | 抽象层不出现任何供应商专有字段；供应商差异收敛在实现内部。 |
| **M-4 取消/超时透传** | `signal` / `timeout_ms` 必须透传；`AbortError` → `cancel`（§8）。 |
| **M-5 无 Key 落盘** | 任何凭据不得写入 `.team/**`、日志或产物文件。 |

> **本设计不包含**：真实 endpooint、鉴权、重试退避策略的具体参数、供应商 SDK 选型。

## §5 Model Response Processing

### 5.1 目标

把 `ModelResponse.text` **严格解析**为执行层可消费的结构化对象。模型输出**不可信**，必须解析 + 校验。

### 5.2 解析产物（设计）

```ts
type ParsedAction =
  | { kind: "answer"; text: string; artifacts?: string[] }           // 终答
  | { kind: "tool_calls"; calls: RawToolCall[]; note?: string }      // 需工具
  | { kind: "checkpoint"; message: string; options?: string[] }      // 请求人工确认
  | { kind: "invalid"; reason: string };                             // 无法解析

interface RawToolCall {
  /** 模型声明的工具名（必须是 context.tools 中的项）。 */
  tool: string;
  /** 模型声明的参数（校验后才下发）。 */
  arguments: Record<string, unknown>;
}
```

### 5.3 解析规则

| 规则 | 说明 |
|---|---|
| **R-1 严格模式** | `expects="json"` 时必须是合法 JSON；解析失败 → `{ kind:"invalid" }`。 |
| **R-2 结构校验** | `tool_calls[].tool` 必须为非空字符串；`arguments` 必须为对象。 |
| **R-3 不信任字段** | 解析器**不**在此处判定工具合法性/权限（那是 §6 Action Validation 的职责）。 |
| **R-4 无执行** | 解析器**绝不**调用工具、**绝不**写盘；纯转换。 |
| **R-5 安全截断** | 超长文本按上限截断（防 DoS），并标注 `truncated`。 |

### 5.4 与本文档「最终执行 Prompt」的关系

- §3 产出 `ExecutionPrompt`（→ 模型输入）。
- §5 把模型输出还原为 `ParsedAction`（→ 动作规划输入）。
- 二者**不含任何 prompt 副本**；prompt 正文始终引用 MyTeam Home。

## §6 Action Planning

### 6.1 核心命题（题干强制）

> **模型输出不能直接执行。**

`ParsedAction.tool_calls` 只是**模型意图**，未经校验绝不触达工具。设计如下链路：

```
Model Response
     │
     ▼
ResponseParser.parse()            // §5 → ParsedAction（不可信）
     │
     ▼
Action Validation                 // §6.2（唯一放行闸门）
     │  逐项校验：
     │   1. tool ∈ context.tools[].tool           （已声明）
     │   2. decl.source 与请求一致                 （host/mcp）
     │   3. decl.allowed === true                  （权限模型）
     │   4. 路径类参数 ∈ allowed_paths ∉ deny_paths（安全域，字符串域判断）
     │   5. 不命中 host_config 黑名单               （~/.config/opencode）
     ▼
Runner（经 ToolInvocationPort → ToolAdapter）     // 二次校验 + 下发
```

### 6.2 Action Validation（执行层内的第一道闸门）

| 检查 | 来源 | 失败处理 |
|---|---|---|
| 工具已声明 | `context.tools[].tool` | `invalid_response`（§8） |
| 来源一致 | `context.tools[].source` | `invalid_response` |
| 权限允许 | `context.tools[].allowed` | `tool_denied`（§8） |
| 安全域 | `context.security.allowed_paths` / `deny_paths` | `tool_denied` |
| 宿主配置黑名单 | `isHostConfigWrite()` 语义 | `tool_denied` |
| 参数形状 | `arguments` 为对象、非空工具名 | `invalid_response` |

> **注意**：执行层校验是**纵深防御的一层**，不是唯一一层。`Runner.invokeTool()` 已做同源校验；
> `ToolAdapter` 做二次校验；`HostPort` 做只读边界。执行层**不得**替代或削弱下游任何一层。

### 6.3 ToolAdapter 是唯一工具入口（题干强制·确认）

```
✅ 允许：AgentExecutor → deps.toolPort.invoke(req) → ToolAdapter → HostPort
❌ 禁止：AgentExecutor → HostPort 直连
❌ 禁止：AgentExecutor → 宿主工具 / MCP 进程
❌ 禁止：AgentExecutor 自行 import fs / 网络 / opencode SDK 执行副作用
```

即：**Action Planning 的产出只能是 `ToolInvocationRequest`，交回 `toolPort`**；
执行体永不自行「执行」动作，只「请求」。

### 6.4 单轮限制（v1.8.4）

- 一次 `execute()` 内：**至多一轮** `tool_calls` 批处理 + 汇总。
- 不做跨轮自主规划（不给模型「看到工具结果再决定下一步」的循环）。
- 该限制使 v1.8.4 可测、可控、无失控循环风险；多轮规划属 §10 OUT。

## §7 Checkpoint Information Flow（修复 v1.8.3 已发现问题）

### 7.1 问题确认（对既有代码的只读核对）

题干指出：`AgentExecutorResult` 中 `checkpointMessage` / `checkpointOptions` **没有完整传递**。
经核对，**问题属实且有多处断裂**：

| 位置 | 现状 | 缺陷 |
|---|---|---|
| `agent-executor.ts` 第 101–105 行 | 成功分支只返回 `{ok, output, artifacts}` | **执行体从不产出** `checkpointRequested/Message/Options` |
| `runner.ts` `normalizeResult()` 第 246–266 行 | 只消费 `execResult.artifacts` / `output` / `ok` | `checkpointMessage` / `checkpointOptions` **被丢弃**，未进入 `RunnerResult` |
| `runner-engine-adapter.ts` 第 103–111 行 | checkpoint 的 `message` 硬编码为 `result.output`，`options` 硬编码为 `["continue","modify","reject"]` | **执行体提供的 message/options 未参与**，被静态值覆盖 |

结论：`checkpointMessage` / `checkpointOptions` 从「执行体」到「Checkpoint Store」**全链路丢失**。

### 7.2 设计完整链路（目标）

```
Executor（AgentExecutorResult）
   checkpointRequested / checkpointMessage / checkpointOptions
        │  ★ 新增：执行体必须真实产出这三字段
        ▼
Runner（normalizeResult）
   ★ 新增：RunnerResult 需承载 checkpoint（见 7.3 契约）
        │
        ▼
Engine（mapRunnerResultToEngineAction → HumanCheckpoint）
   ★ 修正：message ← checkpointMessage，options ← checkpointOptions（不再硬编码）
        │
        ▼
Checkpoint Store（saveCheckpoint → <exe>/checkpoints/<cpId>.yaml）
   message / options / required_action / type / stage 落盘
```

### 7.3 契约修正（设计层，标注为「对 v1.8.3 的增量」）

**① `AgentExecutorResult`（已存在字段，语义强化）**
- `checkpointRequested: boolean`、`checkpointMessage: string`、`checkpointOptions: string[]`
  由执行体在「需要人工确认」时**如实填写**（不再留空）。

**② `RunnerResult`（建议新增只读镜像字段）**

```ts
interface RunnerResult {
  // …既有字段…
  /** ★ 增量：checkpoint 请求的原始信息（status=checkpoint_requested 时非空）。 */
  checkpoint?: {
    message: string;
    options: string[];
  };
}
```

> `normalizeResult()` 在 `checkpointRequested=true` 时，
> 从 `execResult.checkpointMessage/checkpointOptions` 复制到 `RunnerResult.checkpoint`。
> 缺省值（执行体未给 message/options）取兜底：`message = output || "checkpoint requested"`，`options = ["continue","modify","reject"]`。

**③ `mapRunnerResultToEngineAction()`（修正取值来源）**

```
- message: result.output || "checkpoint requested by runner"     // 旧：错误来源
+ message: result.checkpoint?.message ?? (result.output || "checkpoint requested")
- options: ["continue", "modify", "reject"]                       // 旧：硬编码
+ options: result.checkpoint?.options ?? ["continue", "modify", "reject"]
```

`required_action` / `type` / `stage` 的推导保持不变（`type="continue"`、`stage="running"`），
或按执行体语义扩展（本阶段保持最小改动）。

**④ `saveCheckpoint`（已支持）**
`execution-store.ts` 的 `saveCheckpoint` 已渲染 `message` / `options`（第 298–315 行），
**Store 层无需改动**——修复点在 Executor / Runner / Adapter 三处。

### 7.4 不变量

| 不变量 | 说明 |
|---|---|
| **C-1 无损传递** | 执行体给出的 `checkpointMessage/Options` 必须逐字节到达 `HumanCheckpoint.message/options`。 |
| **C-2 兜底不覆盖** | 仅当执行体缺省时才用兜底值；有值则**永不**被静态常量覆盖。 |
| **C-3 无自动通过** | checkpoint 只产生、不自动 resolve（沿用 v1.6.7 语义；人类响应经 `resolveCheckpoint`）。 |
| **C-4 幂等安全** | 重复进入终态时 checkpoint 不重复落盘（沿用 adapter 终态幂等）。 |

## §8 Error Model

### 8.1 设计目标

执行层错误必须归一为**有限类别**，并映射到 `AgentExecutorResult`（再经 Runner → `RunnerErrorKind`）。

### 8.2 执行层错误类别（AgentErrorKind）

```ts
type AgentErrorKind =
  | "model_error"        // 模型调用失败（网络/鉴权/供应商错误）
  | "timeout"            // 推理或整体超时
  | "invalid_response"   // 模型输出不可解析 / 结构非法 / 工具未声明
  | "context_overflow"   // prompt/上下文超出模型窗口
  | "cancel"             // 宿主/调度取消
  | "tool_denied"        // 动作命中权限/安全域拒绝（执行层闸门）
  | "tool_error"         // 工具调用失败（透传自 ToolInvocationResult.error_kind）
  | "agent_error";       // 其余执行体内部错误
```

### 8.3 映射到 `AgentExecutorResult` / `RunnerErrorKind`

| AgentErrorKind | AgentExecutorResult | → RunnerErrorKind | 可重试 |
|---|---|---|---|
| `model_error` | `{ok:false, error}` | `agent_error` | 否（本阶段） |
| `timeout` | `{ok:false, error}` | `timeout`（Runner 超时竞速）或 `agent_error` | 否 |
| `invalid_response` | `{ok:false, error}` | `agent_error` | 否 |
| `context_overflow` | `{ok:false, error}` | `agent_error` | 否 |
| `cancel` | `{ok:false, error}` | `cancel` | 否 |
| `tool_denied` | `{ok:false, error}` | `assertion_error` | 否 |
| `tool_error` | `{ok:false, error}` | `tool_error` | 是（Runner 重试 ≤2，见 runner.ts） |
| `agent_error` | `{ok:false, error}` | `agent_error` | 否 |

> 映射实现落点：执行体内部 `error-model.ts` 归类 → 填入 `AgentExecutorResult.error`；
> Runner 现有 `mapError` / `normalizeResult` 已能把失败折叠为 `RunnerResult.status="failed"`。

### 8.4 判定优先级（从高到低）

```
cancel  >  timeout  >  tool_denied  >  invalid_response  >  context_overflow
        >  model_error  >  tool_error  >  agent_error
```

（如：已取消时即使模型也报错，判 `cancel`。）

### 8.5 不变量

| 不变量 | 说明 |
|---|---|
| **E-1 不外泄裸异常** | 执行体 `execute()` 必须 catch-all，返回带分类的失败结果（沿用现状 106–125 行）。 |
| **E-2 分类有限** | 只用 §8.2 枚举值；不引入供应商专有错误串。 |
| **E-3 可诊断** | `error` 字段附人类可读细节（不含凭据）。 |
| **E-4 不吞错** | 失败必须体现在 `ok=false`，绝不返回 `ok=true` 掩盖。 |

## §9 Security Boundary

### 9.1 Agent Execution Layer 的硬性禁止（题干确认）

| 禁止 | 确认 | 强制方式 |
|---|---|---|
| **绕过 ToolAdapter** | ✅ 禁止 | 执行体只持有 `deps.toolPort`（`ToolInvocationPort`）；无其它工具通道。 |
| **直接访问 HostPort** | ✅ 禁止 | 执行体**不 import** `host-port` / `tool-adapter`；只经 Runner 注入的 `toolPort`。 |
| **写 MyTeam Home** | ✅ 禁止 | 执行层无写路径；`prompt_source` 只读引用；`PromptAssembly` 纯内存。 |
| **修改 OpenCode 配置** | ✅ 禁止 | 执行层不 import 宿主 SDK；不构造任何 `~/.config/opencode` 写目标；`deny_paths` 含 host_config。 |

### 9.2 纵深防御位置（执行层是第几层）

```
第 1 层  Entry        guardHostWrite（拦宿主配置写）
第 2 层  Governance   admitExecution（approved+permission+authorized）
第 3 层  Runner       validateInvocation + invokeTool 校验（工具∈decl, allowed, 域）
第 4 层  ★ Agent Execution Layer（v1.8.4）
            模型输出不可信 → Action Validation（§6.2）→ 只产出 ToolInvocationRequest
            不执行、不直连、不写盘、不联网（除注入的 ModelAdapter）
第 5 层  ToolAdapter  二次校验(permission)+安全域(checkSecurityDomain)+MCP 映射+错误归一
第 6 层  HostPort     只读端点；write 类直接拒（assertion_error）
第 7 层  Store        路径穿越拒绝 + 拒写 home/opencode 配置
```

> 执行层**新增一层闸门（第 4 层）**，但**绝不替代/削弱**第 5–7 层。

### 9.3 执行层安全不变量

| 不变量 | 说明 |
|---|---|
| **SX-1 单通道** | 工具动作只能经 `toolPort.invoke`；无旁路。 |
| **SX-2 只读能力** | 不修改 `context.tools[].allowed` / `permissions` / `security`。 |
| **SX-3 无宿主 import** | 不 import `node:fs`（除只读读取 prompt_source 正文）、不 import 网络/SDK。 |
| **SX-4 无凭据落盘** | 不写 key/token 到 `.team/**` 或产物。 |
| **SX-5 Prompt 不落项目** | 不在 `<project>` 内生成 prompt 副本（§3.3）。 |
| **SX-6 Fail-Closed** | 任一校验失败 → 拒绝下发（不降级为直连/绕过）。 |

> 说明：读取 `prompt_source` 正文属**只读**；写操作一律禁止。
> 若实现选择「不读正文、仅传引用」（由 ModelAdapter 负责读取），则执行层可做到完全无 `fs`。

### 9.4 与 MyTeam Home / 宿主配置的边界

- 读：允许读 `instance.prompt_source`（Home 内只读态）。
- 写：**永不**。`SecurityContext.deny_paths` 含 `myteam_home` 与 `host_config`。
- 卸载：执行层无全局副作用；删插件即恢复原状。

### 10.4 验收断言（设计层）

3. **Prompt 单一来源**：断言 `ExecutionPrompt.prompt_source === instance.prompt_source`，且项目内无 prompt 副本（§3.3 SX-5）。
4. **无真实 Key**：默认装配下 `ModelAdapter` 为 Null 实现，无网络出口、无凭据读取（§4.3 M-1）。
5. **模型输出不可信**：构造非法模型输出用例 → 必得 `invalid_response`，且工具**未被调用**（§5 R-1/§6.1）。
6. **Checkpoint 无损**：执行体给出 `checkpointMessage="X"/options=["Y"]` → 落盘 `HumanCheckpoint.message="X"/options=["Y"]`（§7.4 C-1）。
7. **错误归一**：§8.2 全类别各有对应用例 → 均为 `ok=false` 且分类正确（§8.5 E-2）。
8. **无宿主写**：全程无 `~/.config/opencode` 写、无 `myteam_home` 写（§9.1）。
9. **向后兼容**：既有 `runner.test.ts` / `composition.test.ts` 仍全绿（契约新增字段可选）。
10. **无回归**：全 runtime 测试通过。
