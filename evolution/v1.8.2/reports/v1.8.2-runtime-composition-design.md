# MyTeam v1.8.2 Runtime Composition Design

> 阶段：v1.8.2 — **Runtime Composition（运行时组装层）设计**。
> 前置：v1.6.0 Workspace Binding / v1.6.1 AgentRuntimeInstance / v1.6.3 Tool Bridge Context /
> v1.6.5 Execution Store / v1.6.7 Execution Engine / v1.7.1 Runner Core /
> v1.7.3 Tool Adapter Core / v1.8.1 Runner→Engine Adapter。
> 约束：**只设计，不写代码**；不修改任何实现文件；不修改 OpenCode 配置；不绕过 Tool Bridge / Tool Adapter。
> 状态：设计完成，未触碰任何实现。

---

## §0 定位与范围

### 0.1 本阶段要解决的问题

v1.7.x 已把「单次执行」的全部零件做完，但**没有任何一个模块负责把它们装到一起**：

| 零件 | 现状 | 谁创建它？ |
|---|---|---|
| `ExecutionStore`（函数集合，无类） | v1.6.5 完成 | ❌ 无 |
| `ExecutionEngine`（`EngineDeps` 注入式函数集合） | v1.6.7 完成 | ❌ 无 |
| `Runner`（`RunnerDeps{toolPort, executor}` 注入式） | v1.7.1 完成 | ❌ 无 |
| `ToolAdapter`（`ToolAdapterDeps{hostPort}` 注入式类） | v1.7.3 完成 | ❌ 无 |
| `OpenCodeHostPort`（工厂 `createOpenCodeHostPort`） | v1.7.3 完成 | ❌ 无 |
| `RunnerEngineAdapter`（`executeRunnerResult`） | v1.8.1 完成 | ❌ 无 |

`index.ts` 当前只做到 `resolveWorkspace → ensureTeamRoot → loadPlatform → bridge`，
**从未实例化 Runner / Engine / Adapter / HostPort**。

> **结论：缺少的正是「Runtime Composition（组装层）」。** 它是唯一被允许 `new` / 装配
> Store→Engine→Runner→ToolAdapter→HostPort 的地方。

### 0.2 范围（IN）

- 定义 **Runtime 组装层** 的边界、工厂签名、依赖注入职责、生命周期、测试装配、安全边界。
- 明确「谁创建 / 谁不能创建」每个运行时对象。
- 明确 `index.ts` 插件生命周期如何接入组装层。

### 0.3 范围（OUT）

- ❌ 不写任何实现代码（本文件仅为设计）。
- ❌ 不实现 Agent 执行体（模型推理）。
- ❌ 不实现 Trace 事件总线。
- ❌ 不接真实 MCP 进程生命周期。
- ❌ 不修改 `Resolution` / `AgentRuntimeInstance` / `AgentExecutionContext` 模型。
- ❌ 不修改 OpenCode 宿主配置。

## §1 当前已有模块依赖图（已确认）

### 1.1 绑定/投影链（静态 → 运行实例 → 能力上下文）

```
OpenCodeCtx (ctx.directory)
    │  resolveWorkspace()                     [workspace-resolver.ts v1.6.0]
    ▼
Resolution { myteam_home, project_root, team_root }
    │  ensureTeamRoot()                        [workspace-resolver.ts v1.6.0]
    ▼
.team/{context.yaml, memory/, execution/, trace/, collaboration/}   （只写项目内）
    │  activateAgent(def, res, execCtx)        [agent-instance.ts v1.6.1]
    │     = create → initialize → bind → persist
    ▼
AgentRuntimeInstance {
    id, agent, role, prompt_source, workspace,
    memory_namespace, execution_id, permissions[], status, instance_dir

    │  （Tool Bridge 投影）                     [tool-bridge/context.ts v1.6.3]
    ▼

```

> **依赖方向是单向的**：`Resolution → AgentRuntimeInstance → AgentExecutionContext`。
> 组装层只**消费**这三者，绝不反向修改。

### 1.2 执行链（Store → Engine → Runner → ToolAdapter → HostPort）


### 1.3 关键观察（组装层必须尊重的既有事实）

1. **Store / Engine 是函数式 + 依赖注入**，不是类。Engine 的 `EngineDeps` 是 9 个函数，
   恰好全部来自 Store 的同名导出（`load/save/saveRun/loadRun/listRuns/listCheckpoints…`）。
   → 组装层负责构造 `EngineDeps`（把 Store 函数绑定为 deps）。
2. **Runner 是「编排核心」，不知道 Store**。它只经 `toolPort`（工具下行）与 `executor`（执行体）对外。
   → 组装层必须提供 `executor`（v1.8.2 仍为 stub/mock，真实执行体属未来阶段）。
3. **ToolAdapter 实现 `ToolInvocationPort`**，构造参数是 `(ctx: AgentExecutionContext, deps: ToolAdapterDeps)`。
   → 组装层需要「先有 `AgentExecutionContext`，才能造 Adapter」。
4. **HostPort 从 `client + workspace` 工厂创建**，只读。
5. **`executeRunnerResult` 是 Runner→Engine 的桥**：组装层在「运行一步」时调用它，
   而不是让 Runner 直接碰 Engine。
6. **`Runner` 不写盘；写盘只经 Store**。Engine 是 Store 的唯一写入者。
   → 组装层不得在 Engine 之外写 `<team_root>/runtime/execution/**`。

### 1.4 依赖图（组件视图，含"缺口"）

```
                         ┌─────────────── 缺失：RuntimeFactory ───────────────┐
                         │                                                      │
 Resolution ──┐          │   createRuntime(res, host{client,dir})  ──► MyTeamRuntime
              │          │      │                                               │
 AgentInstance┤          │      ├─ 造 HostPort  (createOpenCodeHostPort)        │
 ExecContext ─┘          │      ├─ 造 EngineDeps(← Store 函数)                  │
                         │      ├─ 造 ToolAdapter(execCtx, {hostPort})          │
                         │      ├─ 造 Runner 依赖 {toolPort=adapter, executor}  │
                         │      └─ 暴露 runStep()（Runner → executeRunnerResult）│
                         └──────────────────────────────────────────────────────┘
```

## §2 RuntimeFactory

### 2.1 目标

提供**唯一入口** `createRuntime()`，把已确认的零件装配为一个不可变句柄 `MyTeamRuntime`。

### 2.2 输入

```ts
// 设计签名（非实现）
interface CreateRuntimeInput {
  /** v1.6.0 解析结果：三根（home / project / team）。 */
  resolution: Resolution;
  /** 宿主注入：OpenCode client 子集（供 HostPort 只读路由）。 */
  host: {
    client: OpenCodeClientSubset;   // @opencode-ai/sdk v1.14.x 子集
    directory: string;              // = resolution.project_root（缺省）
  };
  /** 可选：运行实例 / 能力上下文（若上层已投影好则直接注入）。 */
  instance?: AgentRuntimeInstance;
  execContext?: AgentExecutionContext;
  /** 可选：执行体适配器（本阶段缺省 = stub；真实执行体属未来阶段）。 */
  executor?: AgentExecutor;
  /** 可选：测试用时钟。 */
  now?: () => number;
}
```

> **输入边界**：`createRuntime` 只接收**已解析 / 已投影**的只读对象。
> 它**不负责** `resolveWorkspace` / `ensureTeamRoot` / `activateAgent`（那是 Entry 层的职责）。

### 2.3 输出

```ts
interface MyTeamRuntime {
  /** 只读绑定根。 */
  readonly resolution: Resolution;

  /** 装配好的端口（供上层编排，不暴露内部可变状态）。 */
  readonly ports: {
    readonly hostPort: HostToolPort;          // = OpenCodeHostPort
    readonly toolPort: ToolInvocationPort;    // = ToolAdapter（实现 ToolInvocationPort）
    readonly engine: EngineFacade;            // 见 §2.4
    readonly runner: RunnerFacade;            // 见 §2.4
  };

  /** 单步运行：Runner.execute → executeRunnerResult → Engine 状态推进。 */
  runStep(input: RunStepInput): Promise<RunStepResult>;

  /** 只读能力：装配自检（供测试 / 诊断）。 */
  describe(): RuntimeDescriptor;
}
```

### 2.4 Facade 设计（隐藏函数式细节）

由于 Store / Engine / Runner 是**函数 + 注入**而非类，组装层以 Facade 收敛：

```ts
/** Engine 门面：内部持有 EngineDeps（绑定到 Store），对外只暴露用例方法。 */
interface EngineFacade {
  deps: EngineDeps;                    // 已绑定 Store 的 9 个函数
  transition(id: string, to: ExecutionStatus): Execution;
  pause(id: string): Execution;
  resume(id: string): Execution;
  complete(id: string): Execution;
  fail(id: string): Execution;
  recover(id: string): Execution;
  resolveCheckpoint(id: string, opts: ResolveOptions): Execution;
}

/** Runner 门面：内部持有 RunnerDeps（toolPort=adapter, executor）。 */
interface RunnerFacade {
  deps: RunnerDeps;
  execute(invocation: RunnerInvocation): Promise<RunnerResult>;
}
```

### 2.5 `runStep` 契约（组装层唯一的"执行编排"入口）

```
runStep(input)
  1. 组装 RunnerInvocation（run + instance + context + taskInput + timeout_ms）
  2. result = runner.execute(invocation, runnerDeps)
  3. action = mapRunnerResultToEngineAction(result, run)          [v1.8.1]
  4. { execution, run } = await executeRunnerResult(res, run, result, engineDeps, runId)
  5. return { result, action, execution, run }
```

> **组装层不解读结果、不改状态、不写盘**：状态推进**只能**经 `executeRunnerResult` →
> Engine → Store。组装层是「接线员」，不是「决策者」。

### 2.6 工厂不变量（Invariants）

| 不变量 | 含义 |
|---|---|
| **I-1 单一装配点** | 全仓库只有 `createRuntime` 可以 `new ToolAdapter` / `createOpenCodeHostPort` / 组装 `EngineDeps` / `RunnerDeps`。 |
| **I-2 只读输入** | `createRuntime` 不修改 `resolution / instance / execContext`。 |
| **I-3 无副作用** | `createRuntime` 本身不写盘（HostPort 只读、Store 未被调用）。 |
| **I-4 幂等可重建** | 相同输入可重复调用，得到等价句柄；不共享可变全局。 |
| **I-5 无宿主写** | 工厂与产物绝不写 `~/.config/opencode` 与 `myteam_home`。 |

## §3 Dependency Injection（谁创建 / 谁不能创建）

### 3.1 创建责任矩阵

| 对象 | 创建者 | 依据 | 生命周期 |
|---|---|---|---|
| `Resolution` | **Entry（index.ts）** | `resolveWorkspace(ctx)` | 插件会话级 |
| `.team/**` | **Entry** | `ensureTeamRoot(res)` | 项目级（幂等） |
| `AgentRuntimeInstance` | **Entry / 投影层** | `activateAgent(def, res, execCtx)` | 每次 execution 的 agent 激活 |
| `AgentExecutionContext` | **投影层（Tool Bridge）** | v1.6.3 模型投影 | 随 instance |
| `OpenCodeHostPort` | **RuntimeFactory** | `createOpenCodeHostPort(client, workspace)` | runtime 级 |
| `EngineDeps` | **RuntimeFactory** | 绑定 Store 的 9 个函数 | runtime 级 |
| `ToolAdapter` | **RuntimeFactory** | `new ToolAdapter(execContext, { hostPort, now })` | runtime 级（绑定当前 execContext） |
| `RunnerDeps` | **RuntimeFactory** | `{ toolPort: adapter, executor, now, signal? }` | runtime 级 |
| `Runner`（函数调用） | **RuntimeFactory / RunnerFacade** | `runner.execute(inv, deps)` | 每次 runStep |
| `AgentExecutor` | **外部注入**（缺省 stub） | `CreateRuntimeInput.executor` | runtime 级 |
| Engine 状态推进 | **EngineFacade → executeRunnerResult** | v1.8.1 | 每次 runStep |

### 3.2 明确「谁不能创建」

| 禁止 | 理由 |
|---|---|
| ❌ `Runner` 不能创建 `ToolAdapter` / `HostPort` / `Engine` | Runner 只持有注入的 `toolPort`；它不知道宿主与 Store（v1.7.1 契约）。 |
| ❌ `ToolAdapter` 不能创建 `HostPort` / `ExecutionStore` | Adapter 只消费注入的 `hostPort`；写盘职责归 Engine/Store（v1.7.3 契约）。 |
| ❌ `OpenCodeHostPort` 不能创建 client / 不能启动 MCP | 只读路由；MCP 生命周期归宿主（v1.7.3 契约）。 |
| ❌ `ExecutionEngine` 不能创建 `Runner` / `ToolAdapter` | Engine 只管生命周期；不执行（v1.6.7 契约）。 |
| ❌ `ExecutionStore` 不能创建 Engine / 不能推进状态机 | Store 只做内存↔文件搬运（v1.6.5 契约）。 |
| ❌ 任何模块不能创建 `Resolution`（除 Entry） | 绑定解析是 Entry 独占职责。 |
| ❌ 组装层不能创建 `AgentRuntimeInstance` / `AgentExecutionContext` | 它们是投影产物；组装层只接收已投影对象。 |

### 3.3 依赖注入风格（与既有代码一致）

- **沿用函数注入**：Engine / Runner 已是 `(…, deps)` 风格；组装层构造 `EngineDeps` / `RunnerDeps`。
- **构造器注入**：`ToolAdapter(ctx, deps)` 已是构造器注入；组装层提供 `deps`。
- **工厂注入**：`HostPort` 由工厂创建；组装层调用工厂并注入 Adapter。
- **不做全局单例**：无模块级可变单例；所有依赖显式传递（可测试、可隔离）。

### 3.4 注入方向图

```
index.ts (Entry)
  │ resolveWorkspace / ensureTeamRoot / activateAgent / toolBridge 投影
  │ client ─────────────────────────────────┐
  ▼                                          ▼
createRuntime(res, {client, directory}, {instance, execContext})
  │
  ├─ createOpenCodeHostPort(client, workspace) ──► hostPort
  ├─ bindEngineDeps(store)                     ──► engineDeps   (9 函数)
  ├─ new ToolAdapter(execContext, {hostPort})  ──► adapter : ToolInvocationPort
  ├─ {toolPort: adapter, executor, now}        ──► runnerDeps
  └─ 返回 MyTeamRuntime { ports, runStep, describe }
```

## §4 Plugin Lifecycle（`index.ts` 接入）

### 4.1 当前 `index.ts` 生命周期（已确认）

```
MyTeamPlugin(ctx)
  1. resolution = resolveWorkspace(ctx)
  2. team       = ensureTeamRoot(resolution)
  3. load       = loadPlatform(resolution.myteam_home)
  4. view       = bridge(resolution, team.status)
  5. 返回 hooks { tool: {myteam.status, myteam.execution.admit}, "tool.execute.before", event }
```

> 现状：**没有 runtime 组装**。`myteam.execution.admit` 仅是说明性占位，未接 Engine。

### 4.2 v1.8.2 目标生命周期

```
plugin load (OpenCode 调用 MyTeamPlugin(ctx))
    │
    ▼
1) resolve workspace
    resolution = resolveWorkspace(ctx)
    ensureTeamRoot(resolution)            // 幂等，只写项目内 .team
    │
    ▼
2) create runtime（组装，不执行）
    runtime = createRuntime(resolution, { client: ctx.client, directory: ctx.directory })
    // 只装配：hostPort / engineDeps / adapter / runnerDeps
    // 不投影 instance（尚无 execution），不运行 runStep
    │
    ▼
3) 提供 runtime 服务（hooks 暴露只读/受治理入口）
    返回 hooks:
      - myteam.status          → view（只读聚合，沿用）
      - myteam.execution.admit → 接入 runtime 的准入 + （未来）runStep 门
      - tool.execute.before    → guardHostWrite（隔离守卫，沿用）
      - event(server.connected)→ 日志 isolation=on
    │
    ▼
4) 运行期（按需，受治理）
    当有【已批准 + 已授权】execution：
      activateAgent → toolBridge 投影 → execContext
      runtime.runStep({ run, instance, context, taskInput, timeout_ms })
      → Runner → ToolAdapter → HostPort（只读） → executeRunnerResult → Engine → Store
    │
    ▼
5) 卸载
    无残留：runtime 不写宿主；Store 只写 <project>/.team；删插件即恢复原状
```

### 4.3 生命周期关键点

| 点 | 规则 |
|---|---|
| **load 时组装，但不执行** | `createRuntime` 只在加载期构造端口；不触发任何 `runStep`、不调用宿主工具。 |
| **runtime 服务是受治理的** | hooks 暴露的能力仍受 `admitExecution`（approved action + granted permission + authorized）约束。 |
| **不投影 instance 直到有 execution** | `createRuntime` 允许 `instance/execContext` 缺省；运行期再投影。 |
| **Client 只用于只读路由 + log** | `ctx.client` 注入 HostPort（只读端点）与 `app.log`；不用于写宿主。 |
| **卸载可逆** | runtime 无全局副作用；`.team` 属项目；宿主配置零改动。 |

### 4.4 `index.ts` 改动范围（设计层面）

- **新增**：`import { createRuntime } from "./runtime/composition"`（模块名待定）。
- **新增**：在 step 4 之后 `const runtime = createRuntime(...)`。
- **修改**：`myteam.execution.admit` 的 `execute` 改为调用 `runtime` 的准入/（未来）运行门
  （仍**不生成 Action**、**不绕过 governance**）。
- **不动**：`tool.execute.before`、`event`、隔离守卫、`myteam.status`。

> ⚠️ 本设计**不实施**上述改动；仅给出接入点与契约。

## §5 Test Composition（装配正确性测试）

### 5.1 测试目标

验证**组装层**正确接线（不验证 Runner/Engine/Adapter 内部逻辑，那些已有各自测试）：

1. `createRuntime` 返回完整 `MyTeamRuntime`（ports 齐全）。
2. `hostPort` 是 `OpenCodeHostPort`（只读），`toolPort` 是 `ToolAdapter`。
3. `engineDeps` 的 9 个函数**确实来自 Store**（可注入 spy 验证调用）。
4. `runnerDeps.toolPort === adapter`（同一实例，无旁路）。
5. `runStep` 串起 `Runner → ToolAdapter → HostPort → executeRunnerResult → Engine`。
6. 组装层**不写宿主**、**不越权**、**不改状态（除经 Engine）**。

### 5.2 Mock 策略

| 依赖 | Mock 方式 | 断言点 |
|---|---|---|
| `hostPort` | `MockHostPort`（记录每次 invoke 的 req/opts） | 只读路由；无写端点被调用 |
| `client` | `MockOpenCodeClient`（仅实现 read/glob/grep/list/path 子集） | HostPort 只调用只读端点 |
| `executor` | `StubExecutor`（返回固定 `AgentExecutorResult`） | Runner 经它取结果 |
| `now` | 固定时钟 `() => T0` | duration 可预测 |
| Store | 真实 Store（指向临时 `team_root`）或 spy 包装 | EngineDeps 绑定正确、写盘在 `.team` 内 |
| `resolution` | 临时目录构造 `Resolution` | 隔离域断言 |

### 5.3 测试用例清单（装配层）

| # | 用例 | 期望 |
|---|---|---|
| T1 | `createRuntime(res, {client,dir})` | 返回 `MyTeamRuntime`，`ports` 四项齐全，无异常 |
| T2 | `describe()` | 报告组件来源（HostPort=opencode、toolPort=adapter、engineDeps=store） |
| T3 | `engineDeps.load/save` 调用 | 转发到 Store（spy 命中） |
| T4 | `runnerDeps.toolPort === runtime.ports.toolPort` | 同一 ToolAdapter 实例 |
| T5 | `runStep`（executor 返回 ok=true） | Runner completed → `executeRunnerResult` → execution=completed |
| T6 | `runStep`（executor 请求 checkpoint） | execution=paused + checkpoint 落盘 |
| T7 | `runStep`（toolPort 拒绝 allowed=false） | Runner failed(tool_error)；HostPort **未被调用** |

## §6 Security Boundary（组装层安全边界）

### 6.1 组装层的能力边界（只组装，不决策）

| 允许（组装层能做） | 禁止（组装层不能做） |
|---|---|
| ✅ 构造 `HostPort` / `ToolAdapter` / `EngineDeps` / `RunnerDeps` | ❌ 修改权限（`AgentExecutionContext.permissions` / `tools[].allowed`） |
| ✅ 把 Store 函数绑定为 `EngineDeps` | ❌ 写 `myteam_home`（Source of Truth 只读） |
| ✅ 调用 `executeRunnerResult` 推进状态 | ❌ 写 `~/.config/opencode` / 修改 `opencode.json` |
| ✅ 暴露只读 `describe()` / `status` | ❌ 绕过 `ToolAdapter` 直连宿主 |
| ✅ 传递 `executor` / `now` / `signal` | ❌ 生成 Action / 跳过 governance / 自动提权 |
| ✅ 转发 `resolveCheckpoint` | ❌ 直接写 `<team_root>/runtime/execution/**`（须经 Engine→Store） |

### 6.2 纵深防御（组装层位于第几层）

```
第 1 层  Entry        : guardHostWrite（拦截 write/edit 宿主配置）
第 2 层  Governance   : admitExecution（approved + permission + authorized）
第 3 层  Runner       : 校验 invocation；工具一律经 toolPort
第 4 层  ToolAdapter  : 二次校验(permission) + 安全域(security) + 错误归一
第 5 层  HostPort     : 只读端点；write 类直接拒（assertion_error）
第 6 层  Store        : 路径穿越拒绝 + 拒绝写 home / opencode 配置
────────────────────────────────────────────────────────────
组装层 (Runtime)      : 只做「接线」，不新增也不削弱任何一层；
                        它保证第 3–6 层被正确串联，无旁路。
```

### 6.3 组装层安全不变量（Security Invariants）

| 不变量 | 强制方式 |
|---|---|
| **S-1 无旁路** | `Runner.toolPort` 必须 `=== ToolAdapter`；不存在 `Runner → HostPort` 直连。 |
| **S-2 权限只读** | 组装层对 `execContext` 只读；不重建 `permissions/tools`。 |
| **S-3 宿主只读** | 仅注入只读 `client` 子集；HostPort 无写端点。 |
| **S-4 Home 只读** | 组装层不引用 `myteam_home` 写路径；`EngineDeps` 只写 `team_root`。 |
| **S-5 状态单写者** | 状态变更只能经 `Engine`（`EngineDeps`）；组装层不直接调 Store 写函数。 |
| **S-6 治理前置** | `runStep` 只在 `admitExecution` 通过后被 Entry 调用。 |

### 6.4 失败安全（Fail-Closed）

- 组装失败（缺 client / 缺 resolution）→ `createRuntime` 抛错，**不返回半装配句柄**。
- `hostPort` 缺失 → 不构造 Adapter（避免无宿主通道的空转）。
- 任一端口缺失 → `runStep` 拒绝执行（fail-closed），不降级为直连。
