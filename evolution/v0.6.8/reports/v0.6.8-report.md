# Model Routing Recommendation Layer — v0.6.8 Report

> 阶段：v0.6.8 · Model Routing Recommendation Layer（模型推荐层，只推荐不执行）
> 目标：在 Team → Agent 之下，为「每个任务」建立一个**模型能力档位推荐（Model Recommendation）**：Task → Router → Team → Agent → Model Recommendation → Execution。
> 升级前基线：Agent=30 MCP=5 Skill=26 Workflow=8（**不变**）
> 状态：完成（推荐层设计 + 一致性测试通过，未实现任何自动切换）

## 1. 分层定位

新增 **Model Routing Recommendation Layer**，插入在 Team/Agent 决策与最终执行之间：

```
Task
  ↓  (Router：决定任务是什么)
Team
  ↓  (Team：决定谁负责完成)
Agent
  ↓
Model Recommendation   ← 本层：决定需要什么级别的【模型能力档位】（只推荐）
  ↓
Execution              ← 实际执行（仍归原 Agent / Scheduler）
```

**四层分离（强制）**：PM/Router 决定任务、Team/Agent 决定责任主体、Model Router 决定能力档位、Scheduler 决定时序。

## 2. Model Registry（模型能力档位注册表）

新建 `platform/registry/models/model-registry.yaml`，登记**抽象能力档位**（不绑定任何具体模型 / Provider）：

| model_class | capability_class | reasoning | coding | context | speed | cost | 典型任务 |
|---|---|---|---|---|---|---|---|
| `high-reasoning` | reasoning | very-high | high | large | medium | high | 架构设计 / 复杂调试 / 高风险 / 失败恢复 |
| `fast-coding` | coding | medium | high | medium | fast | low | 简单代码修改 / 重构 / 常规实现 |
| `long-context` | context | high | medium | very-large | medium | medium | 研究 / 论文分析 / 长文档 |
| `general` | general | medium | medium | medium | medium | medium | 默认档位 |

- 配套 `platform/registry/models/model-profile-schema.yaml`（能力等级词汇表 + Profile 字段定义）。
- 配套生命周期策略 `platform/registry/models/policies/model-registry-lifecycle-policy.yaml`（proposed → active → deprecated → retired，由 engops-lead 维护）。

## 3. Routing Policy（推荐规则）

新建 `platform/model-routing/routing-policy.yaml`，规则按序匹配（先命中先生效）：

| 规则 | 匹配条件 | 推荐档位 |
|---|---|---|
| MR-1 | risk=high / 失败恢复 | `high-reasoning` + **human_confirm=true** |
| MR-2 | architecture-design + high complexity | `high-reasoning` |
| MR-3 / MR-4 | research + large context / research-analyst | `long-context` |
| MR-5 | feature + low complexity + execution | `fast-coding` |
| MR-6 | 默认（无特殊匹配） | `general` |

输入：task_type / complexity / risk_level / required_capabilities / context_size（+ 可选 historical_performance、version_quality）。输出：`recommended_model_class`。

## 4. Recommendation Schema（推荐输出结构）

新建 `platform/model-routing/recommendation-schema.yaml`，定义一次推荐的结构：
`task_id / agent / team / requirements{reasoning,coding,context,speed,risk} / recommendation{model_class,fallback,human_confirm,reasoning}`。

**只推荐、不执行（强制）**：输出为推荐策略，供决策参考，**不自动调用模型 / 不自动切换 Provider / 不修改 Prompt / 不自动选 Agent**。

## 5. 系统集成（read-only 接入）

- **PM（project-manager-agent）**：分派时按 routing-policy 读取/写入推荐记录（`platform/model-routing/history/{task_id}-recommendation.yaml`），作为交付给用户的建议策略。
- **engops-lead**：维护 Model Registry 生命周期（proposed→active→deprecated→retired）+ 一致性校验。
- **project-health-agent**：新增 Model Routing 一致性检查（registry↔policy↔schema↔history 引用；「只推荐不执行」不变量；Model Router 不反向决定 Agent）。
- **Analytics**：新增 `analytics/metrics/model-recommendation-metrics.yaml`（推荐数 / 采纳数 / 成功率，只记录不自动优化）。
- **History**：`platform/model-routing/history/model-routing-history.yaml`（批推荐记录，`auto_learn=false`，只记录不学习）。

这些接入均为 read-only，不触发任何执行 / 运行时变更。

## 6. 本阶段明确不实现

- **不实现**自动模型切换、自动模型选择、自动执行、具体模型/Provider 绑定、根据历史表现自动调整档位（均为未来阶段 v0.6.9+）。
